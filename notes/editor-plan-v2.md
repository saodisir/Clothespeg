# 编辑器第二版：细节对齐、参考依据与实施计划

2026-11-02。上一版（矩形/箭头/笔/荧光笔/马赛克/选中/裁剪）已能替代预览，但每个工具只有"颜色 + 线宽"两个旋钮，
保存与完成的语义也含混。这一版把"每个工具的细节"和"退出方式"都定清楚。

## 0. 五条结论

1. **"保存"和"完成"现在只差关不关窗，这不算区分**。真正的区别应该是：写回原文件（不可逆）、另存一份（不动原图）、只进剪贴板。
2. **我们缺一个"不动原图"的出口**。现在唯一的提交方式就是覆盖原文件，而这张图可能是用户从 Finder 拖进来的、别人发来的、手机同步下来的。
3. **马赛克块大小固定 16 图内像素，在没有缩放的面板上等于不可控**：4K 截图缩进 700pt 的窗口，一块只有 2.8pt，看着像压缩噪点而不是打码。
4. **属性条要从"两个共用旋钮"改成"按工具门控的一组控件"**，但控件位置必须稳定，不能因为换工具而左右横跳。
5. **文字工具的大坑不是画字，是编辑**：覆盖一个 `NSTextView` 让光标活着，同时把那一笔从渲染里摘掉，否则双影。

## 2. 保存与完成

### 2.1 现在到底发生了什么

| 动作 | 改磁盘文件 | 关窗 | 进剪贴板 | 可撤销 | 备份 |
|---|---|---|---|---|---|
| 复制 ⌘C | ✗ | ✗ | ✓ | — | — |
| 保存 ⌘S | ✓ 覆盖原文件 | ✗ | ✗ | 只能靠底图 | 本会话首次写前存一份到 `EditorBackups` |
| 完成 ⌘↩ | ✓ 覆盖原文件 | ✓ | ✗ | 关了就没了 | 同上 |
| 关窗 × | 询问：保存 / 丢弃 / 取消 | ✓ | ✗ | — | 同上 |

三个问题：

1. **两个按钮做同一件事**（写回文件），只差关不关窗。用户没法从名字上理解区别，只能背。
2. **"保存"这个词在撒谎**。它承诺的是"存起来"，实际是"把原文件换成带标注的版本"。这张图可能是任何来源，覆盖它是个不可逆的外部动作（备份在 `Application Support` 里，普通用户找不到）。
3. **没有"我不想动原图"的出口**。想留一份干净的、或者想导出一张给同事，只能先覆盖再手动另存。

### 2.2 建议的模型

> 这一节是当初的分析与推荐，**没有按它实施**。用户拍板：不拆三档、不做另存为，只把「保存」改名「写回原图」。
> 实际落地见 §8。留在这里是因为那三个后果的区别仍然是判断依据，将来要做另存为时不用重新想一遍。

把"提交"拆成三种后果不同的动作，各给一个明确的入口：

| 按钮 | 键 | 后果 | 语义 |
|---|---|---|---|
| **完成**（主按钮，高亮） | ⌘↩ 或回车 | 写回原文件 + 关窗 | "我改完了，替代原来那张" |
| **保存**（写回） | ⌘S | 写回原文件 + 留在编辑器 | "存一下，我接着改" |
| **另存为…** | ⇧⌘S | 写新文件到用户选的位置 + 原图不动 | "我要一份副本，别碰原图" |
| **复制** | ⌘C | 剪贴板，磁盘不动 | "我要拿去贴" |
| **关闭 ×** | ⌘W | 有未提交改动才问（完成 / 丢弃 / 取消） | "算了" |

配套的四个小规则：

- **首次写回前提示一次**（每个文件一次，可勾"不再提示"）。文案要说人话：
  "完成会把这张图换成带标注的版本，原图会备份到 <路径>。"——这是唯一一次机会告诉用户他在覆盖什么。
- **保存按钮无改动时禁用**（Framecho 的做法）。按钮状态就是"有没有没存的东西"的指示器，省掉一个脏标记。
- **另存为不自动加卡片**。它是一次导出，写到用户选的位置就结束。想让它上线，用户自己拖进来就行（`Inbox.folder` 已经在监听了）。
- **写回后不重置标注模型**。`source` 仍是打开时那张原图、`marks` 仍在，`flattened()` 每次都从 `source` 重画一遍，
  所以连按两次 ⌘S 写出的仍是同一张合成图，不会重复压（这点我核过代码，不是 bug）。
  它的含义是"磁盘这一版已经包含这些标注"，而内存里那份还是"原图 + 标注"。要不要在写回后把 `source` 换成合成图、
  清空 `marks`（进入新会话），是个取舍：换了更接近真相，但用户就没法接着在原来的标注上改了。**建议保持现状**，
  靠"完成即关窗"来收尾——重新打开文件时读到的是已烘焙的图，标注本来就不在了，这是既定设计。

### 2.3 状态机

```
打开 ──> 干净态（saved = true，保存禁用）
           │ 画/改/删/裁剪
           ▼
        脏态（saved = false，保存启用，关闭要问）
           │ ⌘S 写回成功
           ▼
        干净态（saved = true，保存禁用）
           │ 接着画
           ▼
        又脏了 ──> 再 ⌘S 时整张重新合成（从原图 + 全部标注），不是叠加
```

撤销栈不清、标注不清。写回只是"磁盘上这一版包含了当前标注"，内存里仍是"原图 + 标注"，
所以继续画、继续撤都成立，下一次写回是从原图重新合成整张，不会把标注压两遍。
代价是：写回后按 ⌘Z，画面变了但磁盘没变，要再保存一次才同步 —— 这是可接受且容易解释的。

## 3. 每个工具该有哪些旋钮

现在的 `toolColors` / `toolWidths` 只够覆盖两种参数。扩成一个 `ToolStyle` 结构，每个工具一份：

```swift
struct ToolStyle {
    var color: NSColor
    var width: CGFloat          // 线宽 / 笔刷直径
    var opacity: CGFloat        // 荧光笔、纯色块
    var fontSize: CGFloat       // 文字
    var blockSize: CGFloat      // 马赛克块
    var isFilled: Bool          // 实心矩形/椭圆
    var aspectLocked: Bool      // 裁剪比例
}
```

不是每个工具都用全部字段，但存一份字典比七个类型好维护。

| 工具 | 参数 | 范围 / 默认 | 参考 |
|---|---|---|---|
| 矩形 | 颜色、线宽 | 4pt，红 | Framecho `supportsColorStyle` + `supportsStrokeStyle` |
| 实心矩形（新） | 颜色、不透明度 | 1.0 | Framecho 把它做成独立工具而非开关，因为"选中后改填充"要单独一条历史 |
| 椭圆（新） | 颜色、线宽 | 4pt | flameshot `circle` |
| 箭头 | 颜色、线宽、头长比例 | 头长 = clamp(长/5, 宽, 宽×3)，先用自动，不开放 | 上一轮已实现 |
| 笔 | 颜色、线宽、是否平滑 | 3pt | flameshot `pencil` |
| 荧光笔 | 颜色、线宽、不透明度 | 18pt / 0.38 | Framecho 高亮是独立工具（语义不同：它是"遮住其余"还是"画一笔"，见下） |
| 马赛克（改） | 笔刷直径、块大小、模式 | 26pt / 4…48 像素 / 马赛克·模糊·纯色 | Framecho density 0…1 → 块 4…40；flameshot 的 unredacter 注释 |
| 文字（新） | 字号、颜色、字体、粗体、斜体、对齐 | 16pt，系统字体，左对齐 | flameshot `BASE_POINT_SIZE 8`、Framecho 字号步进 |
| 裁剪（改） | 比例锁定（自由 / 1:1 / 4:3 / 16:9） | 自由 | Framecho `supportsAspectLock` |
| 序号圆（可选） | 序号起点、直径、颜色 | — | flameshot `circlecount` |
| 尺寸标签（可选） | 矩形/椭圆下方显示 px 尺寸 | 关 | Framecho `supportsSizeLabel` |

**关于"荧光笔"的一个分歧**：Framecho 的 highlight 是"只保留框内可见、框外压暗"（`helpText` 里明写 "Draw an area to keep visible; everything outside is dimmed"），跟我们的"半透明黄笔迹"不是一回事。两种都合理，我们保留现在的语义，不跟。

## 4. 属性条怎么排

四条原则，都是从参考项目里抄的判断，不是自创：

1. **常驻不跳动**。Framecho 注释：`Always present so selecting or deselecting annotations never shifts the sections below.` 我们做工具条，对应的是：**控件的槽位固定，不适用的置灰而不是消失**。
2. **按工具门控**。`supportsColorStyle` 之类的布尔量决定谁可用。马赛克没有颜色（现在已置灰），文字没有线宽但有字号。
3. **选中优先**。有选中的标注时，控件作用于它；没选中时作用于"下一笔"。这条已经实现，扩展到新参数即可。
4. **一行装得下**。窗口最小 520pt。现在工具条是 18 个控件、17 个 10pt 间距：七个工具 224pt、撤销重做 52pt、
   颜色 30pt、滑杆 96pt、裁剪/复制/保存/完成约 160pt，加起来约 700pt，已经超过最小窗口宽度。
   再往属性条上加控件（字号、块大小、不透明度、模式切换）会直接挤爆。

所以第二版必须动布局。三个候选：

- **A. 两行**：上行工具，下行属性。窗口 ≥ 74pt 头。好处是都装得下、分组清楚；坏处是吃掉画面高度。
- **B. 属性弹层**：工具按钮长按/右键弹出该工具的设置。省地方，但不可发现。
- **C. 属性条跟随工具收缩**：只有当前工具的参数出现在滑杆位置，其余收进一个"⋯"。最省地方，但换工具时控件内容会变（槽位不变，只是标签和范围变）。

**我建议 C**：固定两个槽位（颜色槽 + 数值槽），数值槽的标签随工具变（线宽 / 字号 / 块大小 / 透明度），范围也随之变。这样布局不跳动、宽度可控，也不需要两行。代价是一次只调一个数值参数——但同一个工具需要两个数值参数的情况只有马赛克（笔刷直径 + 块大小），可以把它俩放进同一个槽位的两段式滑杆，或者给马赛克单独加一个小弹层。

> 用户选了 B（两行），理由原话是"这样你调整得也看得清楚"。实施时两行都按"固定槽位"的方式排，
> 所以这一节的 C 方案里"槽位不跳动"的纪律被保留了下来，只是多加了一行。
>
> **2026-11-02 第八轮推翻了这个布局**（见 §8 末尾「三行托盘」）：两行平铺的按钮和滑杆读起来是一条
> 没有分区的控制带，用户看着像"没做过设计"。现在是三行——上行收尾动作、中行工具、下行属性——每行里
> 按用途分成圆角托盘。槽位纪律不变：不适用就置灰，不增删槽位。

## 5. 功能增补：做与不做

**建议做**（都在本次计划内）

- 文字工具（本节第 6 节 S4）
- 马赛克块大小 + 模糊 + 纯色三模式
- 椭圆、实心矩形
- 裁剪比例锁定
- 选中后二次编辑：双击文字重新进入编辑；选中任意标注后改属性（已有，扩展到新参数）

**可以不做**（列出来是为了以后不用再想）

- 吸管取色、测量工具、尺寸标签：属于"标注给别人看"的需求，我们不是给设计师用的
- 背景/壁纸/水印/圆角阴影：那是截图美化工具（Framecho 有整套 `AnnotationBackground*`，5 个文件 2500 行），跟剪贴板工具的目标不符
- 上传分享、多窗口编辑、图层列表

## 6. 分步实施

每步都能单独验收、单独回退。顺序按"改动面从小到大"排，先把地基（样式模型 + 属性条）换掉，再往上面加工具。

| 步 | 内容 | 验收 |
|---|---|---|
| S1 | `ToolStyle` + `toolStyles: [EditorTool: ToolStyle]` 替换 `toolColors`/`toolWidths`；现有五种工具行为不变 | 换工具、换选中，颜色线宽记忆和现在完全一致 |
| S2 | 属性条改成固定槽位 + 按工具门控（颜色槽、数值槽）；马赛克/裁剪/空选时对应槽置灰 | 逐个切七个工具，槽位不左右移动；马赛克选上时颜色槽灰 |
| S3 | 马赛克：块大小进 `ToolStyle`；`EditorDocument` 的像素化图层改成按块大小缓存（`[Int: CGImage]`） | 块 4 与块 48 两笔同时在画面上，各自是各自的粗细；切块大小不卡 |
| S4 | 文字工具：`NSTextView` 覆盖层、字号/颜色/粗斜体/对齐、双击重编辑 | 点一下出光标，打字时看不到双影；点别处提交；重新打开文件后文字还在（已烘焙） |
| S5 | 保存语义：另存为、首次写回提示、保存按钮按脏状态启用 | 有改动时保存可点、无改动时灰；⇧⌘S 选个新位置，原图未变；关窗三选一文案说清后果 |
| S6 | 椭圆、实心矩形；箭头头长可选 | 三种图形都能画、能选、能改色 |
| S7 | 裁剪比例锁；文字选中后改字号要即时生效 | 选 16:9 拖框，比例锁住；选中一段文字改字号，框跟着长 |

S4 单独估一天，因为覆盖层和渲染要对齐；其余每步都不大。

## 7. 坑（按会咬人的顺序）

1. **文字覆盖层与渲染不一致**。`NSTextView` 自带 `textContainerInset`（默认 2,2）、行高、断行策略。最终渲染用 `NSAttributedString.draw`，两边的度量必须从同一份 `NSAttributedString` 算，否则提交瞬间文字会跳一下。Framecho 的做法是覆盖层自己算 frame，绘制时把正在编辑的那一笔跳过。
2. **⌘Z 在编辑文字时该撤文字**。覆盖层是画布的子视图，事件会先到它；确认 `NSTextView` 自己吃掉 ⌘Z 后我们的 `performKeyEquivalent` 收不到。这条要实测，不能靠推理。
3. **工具字母键与文字输入冲突**。Framecho 在键盘处理里先查 `window.firstResponder is NSTextView` 就直接放行。我们的 `keyDown` 里也要加同样的判断，否则打字打到 "r" 会切成矩形工具。
4. **马赛克缓存爆炸**。按块大小缓存，用户拖滑杆划过 20 个值就是 20 张全图大小的位图。要限制缓存数量（LRU 3～5 张）或者只在松手时生成。
5. **Retina 与块大小的单位**。块大小到底按"图片像素"还是"屏幕点"？Framecho 用点 × 缩放比。我们没做缩放，用图片像素更直观（用户看到的是文件里的样子）。但要在提示里说清楚：图越大，同一个块在窗口里看着越小。
6. **写回与撤销的关系**。写回不改变内存文档，撤销只回退标注、不回退磁盘。用户按完 ⌘Z 可能以为文件也退回去了，
   所以写回成功后要在完成/保存上给一次轻提示（按钮文字短暂变"已保存"），把"磁盘已更新"这件事说出口。
7. **属性条宽度抖动**。数值槽的标签文字长度不同（"线宽 4" vs "块大小 24"），固定宽度 + 等宽数字字体可以避免跳动。

| S1 样式模型 | ✅ | 新文件 `EditorStyle.swift`：`ToolStyle`（颜色/粗细/不透明度/字号/块大小/填充/粗斜体/对齐）+ `StyleField` + 每工具默认值。mark 从「各自存 color/width」改成「各自存一份 `ToolStyle`」，`clone()` 连同样式一起复制 |

| S3 马赛克块大小 | ✅ | 块大小进 `ToolStyle`；`EditorDocument.pixelated(block:)` 按块大小缓存（上限 4 张），选中马赛克后改块大小即时换图层 |
| S4 文字 | ✅ | 新文件 `EditorText.swift`：`TextMark` + `TextLayout`（Core Text 量尺与绘制同源）+ `EditorTextView`。编辑中该 mark 从渲染里过滤掉 |
| S5 保存语义 | ✅ | 按钮改名「写回原图」+ tooltip「用这一版替换原文件」；无未保存改动时按钮禁用；关窗提示改成「把改动写回这张图吗？」 |
| S6 椭圆 / 实心 | ✅ | `ShapeMark` 一个类管矩形与椭圆；填充做成开关而不是独立工具（见下面的偏离） |
| S7 裁剪比例 + 文字改字号 | ✅ | 比例下拉四档（自由/1:1/4:3/16:9），改比例会重塑已有框；选中文字改字号即时生效 |

### 与计划不同的地方（以及为什么）

1. **没有另存为**。用户要求改名而不是拆三档。代价是"不动原图"没有出口，这条记进 backlog（#20 备注）。
2. **首次写回前不再弹窗**。按钮从「保存」改成「写回原图」，加上 tooltip，已经说清了后果；再加一道确认是同一句话说两遍。
   备份仍然照旧（`Application Support/Clothespeg/EditorBackups`）。
3. **实心矩形做成开关**，不像 Framecho 那样单独占一个工具位。理由是两行布局把位置省下来了，而"同一个几何 + 换填充方式"
   用开关表达比用两个工具更准确；代价是选中后切换填充会改动已有那一笔的形状语义（Framecho 靠两个工具避免这点）。
4. **马赛克只做了块大小，没做「模糊/纯色」两种模式**。它们共用一个密度滑杆，但模糊要走 Core Image，另起一段。
5. **文字只做了字号和颜色**，粗体/斜体虽在 `ToolStyle` 里留了字段，但没上控件。

### 顺手修的内存问题

原来马赛克的图层是"缩小再放大"的全尺寸位图：5000×3000 的截图一张 60 MB，按块大小缓存四张就是 240 MB。
现在只存**缩小后**那张（230 KB），绘制时用 `interpolationQuality = .none` 拉伸——视觉完全一样，因为块本来就是放大的原点。
四张缓存从 240 MB 降到 1 MB。

### 计划外的加法：序号圆（S8）

截图里"第一步、第二步"是最常见的标注需求，而它不需要任何新旋钮——直径就是 `width`，颜色就是 `color`，
现有两个槽位够用，所以放在 S7 之后补上。

- `NumberedMark` 只有一个 `center` 和一个由渲染器填的 `number`，**序号不落盘**：
  `EditorRenderer.drawMarks` 边画边数，删除第二颗，后面自动补位；导出走同一个渲染器，所以文件与预览永远一致。
- **计数必须在拆分之前的完整列表上做**。第一版有两个错：草稿单独调一次 `drawMarks`（计数器从 1 重来，
  第三颗在按下到松开之间闪一下「1」），以及把正在编辑的那一笔 `filter` 掉再数（被跳过的那颗不占号，第二颗变「1」）。
  现在 `drawMarks` 带 `skipping:`：跳过绘制但照样计数，画布把草稿 append 进同一个数组、只调一次。
- 数字颜色按填充色亮度选黑白（阈值 0.65）。两位数按 `radius × 1.45` 起算、超宽等比缩，不为了第十颗把所有盘子放大。
- 这一轮用无头渲染验证（`swiftc` 把五个源文件加临时 `main` 编成命令行程序，`flattened()` 出 PNG 再逐张看图），
  因为 Core Text 在翻转的绘图上下文里可能画成反的——这个只能看图发现，不能靠编译通过判断。

### 计划外的加法：文字粗斜体走键盘（S9）

S4 原计划给文字做「字号/颜色/粗斜体/对齐」四组控件，实际只上了字号和颜色。补粗斜体时的结论是：
**不占槽位，走 ⌘B / ⌘I**。两行属性条按 720 最小宽度排满（720 就是底线），为两个按钮重新排版不划算；
而粗斜体对截图标注来说本来就是"打字时顺手一下"的动作，键盘比按钮更顺。
`ToolStyle.isBold/isItalic` 与 `TextLayout.font` 早就在，缺的只是入口，所以这一步的成本几乎全在落点判断上：
正在打字的那个 → 选中的那段文字 → 文字工具的记忆，和色板、滑杆同一套规则。文字工具的 tooltip 里注明这两个键。

对齐仍然没有入口，`ToolStyle.alignment` 是纯字段。截图标注里一段文字不需要排版，这条留在"可以不做"里。


## 9. 第八轮：界面重做与五处修正（2026-11-02）

用户看真机后提了六件事，其中五件是"参数不对"，一件是"整体难看"。

**参数**

| 位置 | 原来 | 现在 | 理由 |
|---|---|---|---|
| 箭头的头 | `clamp(长/5, 线宽, 线宽×3)` | `clamp(长/4.5, 线宽×3.5, min(线宽×6, 长×0.45))` | 原式在小线宽下被压成 3 倍线宽，尖和杆分不出来。现在头至少 3.5 倍线宽，且不超过整支箭的 45% |
| 文字默认字号 | 16 | 32 | 单位是图片像素；Retina 截图上的 16px 只相当于界面小字 |
| 字号上限 | 96 | 100 | 用户指定 |
| 序号直径默认 | 30 | 48 | 要在缩到半屏的截图上认得出 |
| 序号直径上限 | 40（与线宽共用） | 160 | 同一个 `width` 字段对不同工具意义不同，`StyleField.range(for:)` 按工具给范围 |

顺带把**不透明度给了箭头、画笔、文字**：`ToolStyle.opacity` 一直在，绘制也一直认它，
只是这三个工具的第二个槽位空着。"槽位里有真控件"比"槽位里一个破折号"好。

**粗斜体改成按钮**。上一轮做成 ⌘B/⌘I，用户明确否掉：要用图标点选。现在属性行里两个 chip，
和工具同一套开关语言（选中 clay、未选中灰、不适用置灰）。

**打字中途的 ⌘Z 撤字取消**。上一轮给文本框接了独立 undo，用户说"退格键就够，没必要"。
现在 ⌘Z 照旧是撤销整张图的编辑，但这带来一个真 bug：撤销把 marks 换成克隆，
正在打字的那个 mark 就不在图上了，提交时会被当成新标注加回去（多一份）。
修法不是拦截 ⌘Z，而是记一个 `textWasCommitted`：光标打开时它是否已在图上；提交时若它曾
在图上、现在不在，就**什么都不做**——用户已经用 ⌘Z 把它拿走了，加回去等于复活。

## 10. 三行托盘

参照 Framecho 的棚面：**动作在上、工具在中、属性在下**，每一组是浅色圆角托盘。

- 上行：文件名 · 像素尺寸 ·（右）复制 · 写回原图 · 完成。完成是窗口里唯一的 clay 实心按钮。
- 中行：`[撤销 重做] [选择 裁剪] [八个标注工具] … [色板 填充]`。
- 下行：`[字号滑杆 不透明度滑杆 B I] … [裁剪比例 应用裁剪]`。
- 画面加投影：白图放在浅底上没有影子就没有边界，原来那条 separator 边框像在窗口上开了个洞。

三行的宽度预算（720 最小宽度下）：上行约 300、中行约 570、下行约 630，都留有余量。
托盘的实现是 `EditorGroup`（10pt 连续圆角、`labelColor@4.5%` 底、7/5pt 内边距），
按钮是 `ToolChip`（选中 clay@15% 底 + clay 图标）与 `ActionPill`（静音胶囊 / clay 胶囊）。

**踩到的两个坑**：

1. **SF Symbol 会本地化**。`textformat` 在装了 zh-Hans 的 bundle 里画出来是「格式」两个字，
   `character.cursor.ibeam` 画出来是「字」加一根 I 形光标——在一排图标里出现单词。裸二进制
   （没有 .lproj）不触发，所以单独测图标时看不出来。现在文字工具自己画「Aa」模板图。
2. **layer 颜色不跟外观**。`EditorGroup` 的底色是 CGColor，赋值时就把当前外观烧进去了，
   所以走 `updateLayer` + `viewDidChangeEffectiveAppearance` 重设。

**验证方式**：这一轮建立了一个离屏渲染装置（`EditorPreview` + `main.swift` 里的环境变量钩子），
用 `cacheDisplay(in:to:)` 把窗口画进 bitmap，不依赖截屏权限，也不打扰正在用机器的人。
同一个窗口可以按工具、按深浅色、按宽度各出一张图。两个坑：内容视图自己没有底色（窗口画在后面），
所以要先给 bitmap 铺一遍 `window.backgroundColor`，否则深色模式会渲染成"浅色底 + 浅色文字"的假 bug；
外观必须在窗口建好之前定，颜色一旦烧进 layer 就不回头。

## 11. 第九轮：没有可调项的时候

三行排好之后，最难看的地方是第三行的**空状态**：拿光标工具、又没选中任何标记时，那条托盘是两个
`—` 加两个推了不动的滑杆。它读作"坏了"，读不出"这儿现在没有可调的东西"。裁剪工具也是同一态。

改成分情况给内容，而不是给一个恒定的骨架：

| 状态 | 第三行左边 |
| --- | --- |
| 光标、未选中 | 一句 11pt 淡字：点一下图上的标记，就能改它的大小和颜色 |
| 裁剪 | 一句同样的字：拖出裁剪框，回车应用 |
| 序号圆（只有一个槽） | 只留「大小」一个滑杆，不留第二个空槽 |
| 非文字工具 | 不出现 B / I |
| 其余工具 | 两个滑杆，和原来一样 |

托盘本身不消失（不搬邻居），消的是里面没有意义的那几格。

**坑一：`isHidden` 不把宽度还回来。** 在 `detachesHiddenViews = false` 的前提下，隐藏的 arranged
subview 仍在布局里占着它原来的宽度：托盘藏了，句子却被顶到 x≈460（托盘右侧）而不是左边 14。
`NSStackView` 里正确的"不显示并把位置让出来"是 `setVisibilityPriority(.notVisible, for:)`——
同样的隐藏、同样的位置保留，但宽度收回去。这个坑的判据很直白：句子在哪儿，一眼就能看出托盘还在不在。

**坑二：隐藏的视图会被"出界"检查报到。** `reportFitting` 遍历所有 subview，被藏起来的标签停在
(-2, 594) 这种地方，于是每次渲染都多出三行"outside the window"，把真正的问题埋掉。加了
`isHiddenOrHasHiddenAncestor` 就直接跳过。

**坑三（harness 自己的）：切完九个工具最后停在枚举的最后一个。** 新增的"渲染前先把九个工具各切一遍"
本来是为了让 hide→show 的顺序被验证到（返回的控件会不会排到末尾）。但它结束时停在 `allCases` 的
最后一个 `.crop`，而不指定工具的那张图就悄悄变成了裁剪态——发现方式很土：两张不同状态的 PNG
字节数一模一样。现在 harness 显式写 `?? .select`，不继承上一轮的残留。

顺序确实没有乱：循环之后逐工具渲染，文字工具那一行仍是「字号 / 滑杆 / 不透明度 / 滑杆 / B / I」，
序号圆只剩「大小」加一根滑杆。

**最后加的一条线**：`EditorRule`（原来写成一根竖线，一直没人用）改成第三行下面的通栏 1pt 横线，
`labelColor@12%`，和画面外框同一笔。没有它，三行工具和放画面的那块底是同一张面，整个窗口读作
"一张图上面有几颗按钮"而不是"一把工具加一张纸"。截图里加不加这条线的差别，比这一轮任何一处调色都大。

## 12. 第十轮：工具搬到下边，颜色换成七个点

四条全来自同一份截图意见，其中两条改变了窗口的形状。

### 12.1 编辑栏搬到窗口底部

窗口现在是：**顶栏（文件名 · 尺寸 · 复制 · 覆盖 · 完成）／上横线／画面／下横线／工具行／属性行**。
顶栏是"这张纸"的身份，底部两行才是工作的地方。两个 1pt 横线把画面框在中间。

搬下去之后 `ground` 这个"三行整体"的容器失去意义，改成 `header` 与 `footer` 两个容器：
header 46pt 固定，footer 92pt 固定（两行各 46），画面吃剩下的。窗口最小高度 420 时画面还有 280pt。

**一个只有搬下去才暴露的 bug**：裁剪之后顶栏的像素尺寸不更新。`sizeLabel` 原来只在 `load()` 里写一次，
而裁剪改的正是这个数——顶栏会一直报着打开时的大小。现在 `pictureChanged()` 顺手重写一次，
它本来就是"图变了"的唯一入口。

### 12.2 颜色：七个点 + 一个更多

`NSColorWell` 撤掉，换成 7 个 `ColourDot`（红橙黄绿青蓝紫，系统色，浅深两种外观各自调过）+
第 8 个画着加号的点。加号点打开 `NSColorPanel`；面板里选出的非常规颜色落在加号点上（`borrowed`），
所以**属性行永远显示得出下一笔是什么颜色**，不管它是不是货架上的。

- 色点 18pt 格子里画 12pt 圆，选中时外面套一圈 1.5pt clay 环。18 而不是 20：8 个点按 20pt 排，
  720 最小宽度差了 4pt，窗口被自己撑到 724。这是"最小宽度"这类常量最容易失守的地方——它不是被算错的，是被悄悄撑开的。
- `NSColorPanel.shared` 是全进程一个 target，而且**没有读 `target` 的接口**（能 set 不能 get）。
  所以用一个 `weak static var panelOwner` 记住是谁借的，关窗时还回去；不还的话下一个编辑器的面板会往一个关掉的窗口报信。
- 颜色放进属性行之后，**工具行只剩工具**。填充开关跟着颜色走（都是"这一笔怎么上色"）。

### 12.3 裁剪：不裁剪的时候，裁剪的东西不出现

- 比例下拉从"常驻但置灰"改成**只在裁剪工具下出现**，它和色点轮流占属性行右侧同一个槽。
  上一轮记的"控件不隐藏、只置灰"在这里让位：一个只在一种模式下有意义的下拉，置灰等于在行里放一件装饰。
- **「裁剪」按钮取消**，双击裁剪框即应用，回车也行。双击的两下里第一下必须不改变任何东西——
  `mouseDown` 在裁剪态只看 `clickCount == 2` 且已有框，其余一律早退。
- 没有按钮之后，"回车"这一键的主人也换了：框在时回车应用裁剪，不在时还是完成。实现是
  `cropChanged` 让完成胶囊**交出** key equivalent，由画布的 `keyDown` 接住（框在 → `.crop`；不在 → 交给 super，落到胶囊上）。
- 双击是否真的走到，用脚本发事件验过（见 12.4），不靠读代码。

### 12.4 裁剪动作的脚本验收

`CLOTHESPEG_EDITOR_PREVIEW_DRILL=1` 会在渲染前用 `NSEvent.mouseEvent` 造一串事件，
按 拖出框 → 单击 → 双击 的顺序发给画布，打印每一步的像素尺寸：

```
drill: 1600×857 → drag 1600×857 → one click 1600×857 → double click 345×242
drill: double-click crops, single click does not
```

中间那两次"没变"和最后一次"变了"一样重要：只测双击的话，单击也触发裁剪的 bug 照样通过。

**一个绕不过去的坑**：事件不能走 `window.sendEvent`。窗口不是 key 的时候，第一次 mouseDown 被窗口拿去
激活自己（click-through），而窗口从来没 `orderFront` 过就永远不是 key——于是所有事件被静默吞掉，
表现为"代码没问题但什么都没发生"。现在直接调 `canvas.mouseDown/Dragged/Up`，命中测试单独用
`hitTest` 断言一次（事件真正带的信息里，只有坐标是 `sendEvent` 额外提供的）。

### 12.5 顺带：裁剪后不再放大

`imageRect` 原本是纯粹的"填满画布"，裁成 345×242 的角之后会被放大到 2.4 倍填满窗口——一张自己插值出来的图。
现在 `factor = min(fit, 1)`：**只缩小不放大**，1 点是 1 像素的上限。裁剪完立刻看到的是清晰的小图，
而不是糊掉的大图。

## 13. 第十一轮：三种离开的方式

原先是「复制 · 覆盖原图 · 完成」。用户的疑问很准：**完成 = 覆盖 + 关窗**，同一件事说两遍，
而且"完成"这个词比"覆盖"含糊——它没说文件到底改没改。改成三种互不重叠的离开方式：

| 按钮 | 做什么 | 关窗 | 碰文件 |
| --- | --- | --- | --- |
| 取消 | 什么都不做 | 是（脏的话弹三选一） | 否 |
| 复制 | 把这一版放进剪贴板 | 是 | 否 |
| 覆盖 | 写回原文件 | 是（写成功才关） | 是 |

左到右按"后果的轻重"排，覆盖是窗口里唯一的 clay——它是真正的提交，也是唯一改磁盘的动作。

### 13.1 复制为什么也关窗

三个按钮回答的是同一个问题："这一趟怎么结束"。如果复制不关窗，那一组里就有两个出口加一个工具，
用户还得再找"完成"——正是这次要删的东西。

复制关窗**不弹丢弃确认**：用户正在看的那一版已经在剪贴板上了，没有东西可丢；文件从来没被碰过，
这正是这个按钮的意义。

`⌘C` 仍然是"复制、留在这儿"。同一个动词的两半（复制后留下 / 复制后走人）是两条动作，不是一条带开关的。
按钮和快捷键在这里不一样，是刻意的：常按保存的人不会希望 ⌘S 顺手关窗，常按复制的人也不会希望 ⌘C 关窗。

### 13.2 灰掉的 clay 不是 clay

覆盖在没有改动时置灰（按钮就是脏标记的指示器，这条从第五轮就有）。
但 `ActionPill` 的 `isPrimary` 原先无条件填 clay：**灰掉的主按钮还是一颗实心陶土橙**，
于是"没东西可写"看起来像"快按我"。现在 `isPrimary && isEnabled` 才上 clay，
否则退回普通胶囊——颜色是"这是活着的提交"的信号，一半浓度的信号仍然是信号。

### 13.3 回车、⌘S，以及为什么干净的图上不能写

回车原先挂在完成上。现在挂在覆盖上，而覆盖会置灰，所以**干净的图上按回车什么都不发生**——
这是对的：没有改动就没有提交。

`⌘S` 走 `perform(.save)`，那里加了 `guard saved == false`。不只是为了语义：
`write()` 第一次执行会先 `EditorStore.backup(url)` 复制一份原图，所以在没有改动的图上"保存"会
凭空产生一份备份并重写一遍文件。一个不该有副作用的动作，副作用藏在两行之后。

### 13.4 删掉的东西

窗口关掉了，就没有地方显示「已覆盖」这句回执 —— `written()`、`writeGeneration`、
`ActionPill.isNote`、`setTitle(_:)`、`minimumWidth` 一起删掉。当初 `minimumWidth` 存在的理由
（"已覆盖"比"覆盖"多一个字，按钮会抖）随着回执一起消失。

### 13.5 顺带修的两个词条重复

`.strings` 不允许同名键，后定义的静默覆盖前面的，而 `plutil -lint` 不检查这件事。

1. **`"Done"` 定义了两次**（`完成` 和 `确定`），后者赢了 —— 所以设置页的 Done 按钮
   和便签提醒面板的 Done 一直显示「确定」。删掉后一条，两处回到「完成」。
2. **我这一轮新加的七个颜色词条撞了便签颜色**：`"Red"` 等已经有 `红色` 的定义，我加 `红` 会把便签那边改掉。
   删掉五个，只保留 `青色` / `紫色` 两个新的。

查重脚本（每次动词条都跑一遍）：

```python

        for l in open(p) if re.match(r'^"((?:[^"\\]|\\.)*)"\s*=', l)]
```

### 14. 填充开关的两处修正（看渲染图时发现的）

`fillToggle`（`square.fill`）原先常驻在颜色托盘末尾，工具不是矩形或椭圆时只是置灰。
**一个灰掉的实心方块看起来就是一块空槽**——和第三轮那排"死滑块"同一个病：不可用的控件
留在原位，读作坏掉。改成 `colourTray.show(fillToggle, fillable)`，只有矩形与椭圆带它。

即使在可用状态下，`square.fill` 开与关画的是同一个方块，只换颜色——一个开关说不清自己
在什么状态。新增 `ToolChip.symbol(_:)`，图标跟着状态换：关 = `square`（空心轮廓），
开 = `square.fill`（实心）并带 clay 底。

判据：同一条托盘上的每个控件，要么说得出"我现在是什么状态"，要么不出现。

## 第十二轮：名字只出现一次，工具回到头顶，一图一窗

### 15.1 一个名字就够了

窗口标题栏写着文件名，标题栏下面那条横幅又写一遍，还给了一遍像素数。
同一件事在一屏里说两次，第二次就成了噪音。现在：**名字和尺寸都在系统标题栏**
（`cam-default.png · 1600 × 857`），横幅整条撤掉。裁剪改了尺寸，`updateTitle()` 重写标题——
标题停在打开时的像素数，就是在骗人。

### 15.2 取消删掉，关窗就是取消

「取消」和红灯做的是同一件事。它还占着动作那一排最左边的位置，
而那一排左边紧挨着工具——误点一下就是把图画丢了。删掉。
关窗时的三选一还在（`windowShouldClose`），因为那个「取消」是「别关」，不是「别存」。

顺手修了那里的一个洞：`guard saved == false, document.marks.isEmpty == false`。
**裁一刀也算改动，但裁剪不产生标记**，于是只裁不画的时候关窗一声不吭地丢掉了结果。
现在只看 `saved`。

### 15.3 复制与覆盖不关窗，按下要出声

关窗是交通灯的事，两个动作只管把这一版送出去。按钮之所以原来敢关窗，是因为
「关窗」就是它们的回执。现在窗口留着，回执得另外给：图标变 √，1.1 秒后变回来。
按每个按钮单独计代，共享一个 Timer 的话，先按复制再按覆盖会让复制的 √ 卡在那儿。

复制和覆盖现在是一对**图标**（`doc.on.doc` / `square.and.arrow.down`），
挤在工具行最右端自己的托盘里——一行图标里塞两个词，读起来是两种东西共用一个架子。

### 15.4 编辑栏回到头顶

上一轮把两行搬到窗口底部，理由是「手在图片附近」。用起来不对：手其实在屏幕上方
（交通灯那一带），伸到图片下面去改颜色比伸手向上远。现在
**工具行 + 两个动作占第一行，属性行第二行，一条横线，下面是画布**，底栏取消。

### 15.5 一图一窗

`ImageEditor` 从「一个 controller」改成 `[URL: Controller]`。同一条 URL 再打开是
把已有窗口提到前面——两个窗口写同一个文件才是真的要防的事；不同图各开一个。

### 15.6 默认值与记忆

线宽 6、字号 40。**改过的值记在 `EditorStyleStore`**（UserDefaults + JSON，颜色存 sRGB 分量），
下次开窗沿用。只在「没选中标记」时落盘：选中一个箭头改颜色是在改那一个箭头，不是改默认。

### 15.7 比例

补齐成 9 档：自由 / 1:1 / 4:3 / 3:2 / 16:9 / 3:4 / 4:5 / 9:16 / 2.35:1。
后三档是有人真要用的：4:5 是 Instagram 信息流，9:16 是竖屏视频封面，
2.35:1 是公众号头图 900 × 383。查过一轮现行尺寸，1:1 / 4:3 / 3:4 / 16:9 / 9:16 / 4:5 / 2.35:1
覆盖了国内主流投放位。

位置也换了：原来挂在属性行最右边，裁剪时整行只剩它一个，看着像剩下来的。
现在它是**裁剪工具下属性行的第一个控件**，紧跟着提示文字——比例和线宽是同一类东西
（关于「接下来这一笔画多大」的数字），应该在同一个位置出现。

### 15.8 验收多了两样

- 截图改为拍 **window frame view**（contentView 的 superview），标题栏才在画面里。
- `CLOTHESPEG_EDITOR_PREVIEW_CHECK=<第二张图>`：同一张图连开两次应得 1 个窗口、
  再开一张应得 2 个；`EditorStyleStore` 写入 17 读回 17（读完把用户原来的值放回去）。

### 15.9 还没解决的

用户说「对话框不好看」——指的若是这个编辑器窗口，这一轮已经重排（标题栏 + 两行 + 画布）；
若指的是关窗时那个系统三选一 `NSAlert`，它还是系统默认长相，没动。

## 第十三轮：一条工具栏、四个图标、一层点阵

参考图是 CleanShot 那种：一条悬在图片上的圆角托盘，中间用细竖线分组，选中项是一块染色方块。
这一轮把窗口往那个方向收。

### 16.1 四个托盘合一个

`[撤销重做][选择裁剪][八个标记][复制覆盖]` 曾经是四个托盘。四个圆角矩形并排，
看起来像四块板子；参考图里是一块。现在是一块托盘 + 三条 1pt 竖线（`EditorSeparator`）
分组，并且**居中**——一块托盘靠左会剩下右边三分之二空白，读作「这条工具栏没做完」。

### 16.2 复制/覆盖换衣服

`ActionPill` 整个删掉，两个动作改用 `ToolChip`：同样的 30×26、同样的图标语言、同样的
「点亮」样式（clay 15% 底 + clay 图标）。**一个窗口只该有一种「亮」的含义**，动作的
按下反馈就借这一种：图标变 √，点亮一秒，然后灭回去。原来那个胶囊是窗口里唯一一种
别的形状，正是它让这两颗按钮看起来是另一个窗口搬来的。

`ToolChip` 的禁用色也从 `.tertiaryLabelColor` 换成 `labelColor@32%`：系统那个三级色
在 17pt 图标上不是「不可用」，是「不存在」，一颗灰到看不见的覆盖等于没有覆盖。

### 16.3 填充回到数值身边

`fillToggle` 从颜色托盘的尾巴挪到属性行，紧跟两个滑块。它是「怎么画」，不是「什么颜色」；
夹在七颗圆点后面时，那颗方按钮读作第八种颜色。

图标换成 `square.inset.filled`（框里一块实心）。原来的 `square`/`square.fill` 真正的毛病
不是不够黑，是**和矩形工具的 `rectangle` 撞脸**——同一个空心方框，只能靠大小分辨。

### 16.4 铅笔与马赛克

- `pencil` → `pencil.tip`：笔尖，和荧光笔的粗笔头一眼分得开。
- `square.grid.3x3.fill` → `circle.grid.3x3.fill`：马赛克把画面打成色块，方点阵在
  17pt 上读作「表格」。

### 16.5 点阵底

画布上铺 12pt 间距、1.6pt 大小的圆点，`labelColor@10%`。理由只有一个：**这个编辑器
最常见的素材就是灰色 App 的截图**，灰图放在灰底上，图片的边界会消失。点阵只在图片外，
所以它回答「图到哪儿为止」而不污染图片本身。

实现是 `NSColor(patternImage:)` 平铺 12×12 的 tile，不是画几千个圆；tile 里烧了颜色，
所以 `viewDidChangeEffectiveAppearance` 里丢掉重建。

### 16.6 斜体：三段都验过

用户报「斜体好像不起作用」。分成三段分别验：

1. **字体层**：`NSFontManager` 与 font descriptor 两条路都得到 `.SFNS-RegularItalic`，
   真的画出来和正体差 4165 个像素——字体没问题。
2. **按钮 → 样式**：`CLOTHESPEG_EDITOR_PREVIEW_ITALIC=1` 沿点击的真实路径
   （找到斜体 chip，`sendAction` 给它的 target）按下，`style.isItalic` 从 false 变 true。
3. **样式 → 插入符**：同一个演练顺手打开光标，读到字体是 `.SFNS-RegularItalic`；
   关掉后回到 `.AppleSystemUIFont`。

演练按两次，把工具放回原处——一个会改用户偏好的检查不是检查，是副作用。
结论：这一版里斜体是通的。若仍然不斜，要问清是「正在输入时不斜」还是「提交后不斜」。

## 第十四轮：三条浮条、一个抽屉、一层缩放

用户拿了两张参考图（`Clipboard_Screenshot.png` 那条悬在点阵上的胶囊、`-1.png` 那个
「撤销重做一块、38% 加菜单一块」的布局），提出三点分布 + 悬浮 + 属性栏默认收起 + 加缩放。
问了三件事之后定下来：属性条**跟着工具走**、缩放**并入右侧动作条**、点阵**固定 12pt**。

### 17.1 为什么是三块

一整条居中，撤销和覆盖挤在同一串里，只能靠图标分辨轻重，位置本身不说话。
三块各答一个问题：左上「之前发生了什么」（历史就在那儿）、中间「手上是什么」、
右上「这一趟怎么结束」——离工具最远，误点的代价最小。

三块不是画上去的三块，是三个锚点：左 pinned 到 leading+16，右 pinned 到 trailing−16，
中间 centerX。这个排法有个没有警告的失败模式：**窗口窄到三块滑进彼此**，
任何东西都没出窗口，`reportFitting` 看不见。所以补了一条测距自检：

```
980 宽 → bars: three, tightest gap 107 pt
820 宽 → bars: three, tightest gap 27 pt
760 宽 → bars: OVERLAP by 2 pt
```

最小宽度因此从 720 抬到 820。这个数是量出来的，不是拍的。

### 17.2 悬浮：把 93 点还给图片

原来两行固定占 46 + 46 + 1 = 93 点，无论是否正在改颜色，都从图片那份高度里扣。
现在画布铺满整个 contentView，三条浮条压在上面，常驻高度 0。

浮条不能沿用托盘的 5% 墨色——那是「和窗口同一种材料」，压在图上是「把图抹了一层」。
新面 `EditorInk.float`：近不透明的浅/深面，加一圈 14% 发丝边和一道阴影。
不用 `NSVisualEffectView`：那块会每帧重新模糊画布下面，拖拽时正好是最贵的时候。

### 17.3 抽屉

一套控件（比例 / 两个滑块 / 填充 / B I / 八个色点 / 一句提示）挂在中间那条下面 8 点，
同材质、同圆角，读作「中间那条拉出来的抽屉」，不是第二条浮条——两块平级的浮层会显碎，
也分不清谁属于谁。

出现规则（用户选的「跟着工具走」）：选到任何有东西可调的工具就出现，回到「选择」就收起；
**再点一次当前工具收起来**，再点一次放回来。只有 chip 有这个第二含义，键盘字母没有——
按一下正在用的工具不该把马上要用的数字藏起来。

打开一张图的默认状态（选择工具、什么都没选）抽屉不存在，这就是「腾出位置」的全部意思。

### 17.4 缩放：这一轮唯一有回归风险的部分

模型就一个字段：`zoom: CGFloat?`，nil = 适合窗口（窗口变了自动重算），否则是点/像素。
`imageRect` 是唯一的变换点，`scale` 从它推出来，所以箭头头部、文字框、插入符、裁剪框、
命中松弛全都跟着走。平移是 `pan: CGSize`，夹紧到「图片比窗口大的那部分」，
适合窗口时归零。

手势：`−`/`+` 各 1.25 倍、百分比按钮落菜单（适合窗口 ⌘1 / 放大 ⌘+ / 缩小 ⌘− / 50 / 100 ⌘0 / 200 / 400）、
滚轮与双指平移、捏合缩放。空格留空——文字工具要打空格。

验证方式是「用同一个换算瞄准，再读回存了什么」：

```
zoom: fit, 100% → stored 113,88 169×133
zoom: 200%, 200% → stored 113,88 169×133
```

两种缩放下存下来的矩形完全一样，说明变换和绘制没有各说各话。
（第一版读到 117,117 206×126，差 3 点四周各 3 ——那是 `ShapeMark.bounds` 把线宽一半
算进了命中框，读错了属性，不是画错了。）

### 17.5 拖拽时淡出

浮条压住图片顶部只在一种情况下是问题：图够高，而人正在顶部画。所以淡出绑在
**拖动**上（`mouseDragged` 才触发，单击不触发）——单击也淡一下会比遮挡更烦。
淡到 0.32，抬手 0.22 秒回来。

### 17.6 顺带查出两个真 bug

1. **色点的「选中环」早晚不一样**：`EditorStyleStore` 存的颜色是 sRGB 定值（按保存时的外观
   解析过），色点持有的是动态系统色。深色模式下两者不等，预设色点上的环消失，
   第八个点反而显示成「自定义色」。`ColourDot.matches` 改成在 aqua 与 darkAqua 下各比一次。
   这是渲染深色图时看出来的，不是读代码读出来的。
2. **点阵太淡**：`labelColor@10%` + 1.6pt 在白窗口上放大 3 倍才看得见，等于没铺。
   改 14% / 1.8pt。
3. `EditorRule` 删掉——不再有「盖子」需要画那条线。

### 17.7 验收

```
zoom: the transform agrees with the drawing at both scales
drill: double-click crops, single click does not       200 × 140
italic: false → true → false; the caret follows it
check: same file twice → 1 window(s); then a second file → 2 window(s)
check: wrote width 17, read back 17.0
preview: everything fits
bars: three, tightest gap 107 pt at 980 wide
```

裁剪演练顺手改成瞄准**图片坐标**（原来是裸视图坐标，注释写的是图片坐标，代码不是）。
两者在 fit 下碰巧重合；一旦先跑缩放演练，同一个演练会得到 100×70 而不是 200×140——
一个只在默认状态下成立的检查，等于没有检查。

## 第十八节（第十五轮）：十个百分点、一只移动的手、箭头回到按钮上

三件事，都是用户上手十分钟之内撞到的。

### 18.1 步进改成十个百分点

原来按一次放大是 ×1.25。从 100% 出发得到 125%——一个没人要过的数字，而且下一档是 156%、
再下一档 195%。倍数是「算出来的百分比」，用户要的是「一档」。

现在一次 ±10 个百分点，**并且第一步先对齐到整十**：fit 落在 73% 时按一下是 80%，不是 83%。
之后每一档都正好差 10，阶梯读作 10, 20, 30…

菜单里的 50/100/200/400 是另一件事（直接跳），保留：一个是从当前往前挪一格，一个是回到一个固定档位。

### 18.2 一只移动的手

缩放之后没法挪画面——滚轮平移早就有，但没有人会先去滚一下再决定用不用。

新增第 11 个工具 `hand`（G，grab）：拖动即平移，光标开口手、按下握拳。
它和选择放在一起，因为两个都是「指着画面、但不改画面」。键盘给 G 是因为 H 被荧光笔占了，
后加的工具不该把先来的字母抢走。

实测：200% 下拖 (60, 40)，画面正好移 (60, 40)，画上不多一个标记。

### 18.3 光标：落在按钮上不该还是十字

画布对整块区域声明了 tool cursor（画笔工具 = 十字），浮条是它上面的兄弟视图。
AppKit 的 cursor rect 是「谁在前谁说话」，但**前提是前面那个视图自己也声明了一个**：
浮条不声明，光标就穿过去落到画布上，于是手伸向撤销时被告知「你在瞄准照片」。

`EditorGroup.resetCursorRects` 里 `addCursorRect(bounds, cursor: .arrow)` 一行解决。
这是渲染看不出来的那一类问题——离屏截图里没有鼠标。

### 18.4 最小宽度 820 → 860

第 11 个工具让中间那条宽了 33 点，820 宽时三块之间只剩 11 点，读作「一条浮条中间断了一下」。
860 留 31 点，和上一轮定的余量一致。这条只能量出来：`bars: 860 → 31 pt`。

### 18.5 验收

```
zoom: 10-point steps 73% → 80% → 90% → 80% → 70%
zoom: from 50%, ⌘0 → 100%, ⌘1 → 100%, ⌘− → 90%
pan: dragged 60,40 → moved 60,40; marks 2 → 2
pan: the hand moves the picture and draws nothing
bars: three, tightest gap 31 pt at 860 wide
```

光标那一条**没有自动化**：离屏渲染里没有指针，cursor rect 只能靠人看一眼。

## 第十九节（第十六轮）：开在面板下面、手与缩放同一条、三块各二

三条都是用过之后说的，不是设计时想到的。

### 19.1 编辑器开在呼出面板下面

原来的位置是屏幕居中，也就是面板正压着的那一块。于是编辑一张图要先等面板收回去——
一个「我要马上改一下」的动作被排在一次动画后面。

现在开窗时按面板实际的下边缘摆：`LinePanel.current`（弱引用静态，`AppDelegate` 里赋值）
给出那一条的真正底边，退路是 `visible.maxY - Layout.clipboardDepth`。

几个刻意的选择：

- 屏幕取**指针所在那块**（`LinePanel.screenUnderPointer()`），不是 `NSScreen.main`。
  面板是在指针那块屏上叫出来的，编辑器跟到别的屏上是另一种「白等一次」。
- 上沿贴面板下边再让 12 点，左右各让 12 点，高度夹在 `visibleFrame` 之内且不低于
  `minSize.height`——屏幕矮的时候宁可矮一点，也不要开出一个拖不动的窗。
- 位置只在开窗时算一次。用户挪过之后不该被下一次 `layout` 拽回去。

验收打的是这一句：

```
place: strip ends at 862 (no panel on screen — the depth it would be), screen bottom at 81; window 365,122 980×728
place: the window opens under the strip and on the screen
```

括号里那句是这套演练唯一诚实的缺口：离屏渲染的时候面板没有起来，走的是退路分支，
真面板那条路上的算术是同一行。**这条不能靠截图证明，只能靠真机上开一次看一眼。**

### 19.2 手挪到缩放旁边

上一轮把 `hand` 当第 11 个工具排进工具列表，位置在「选择」旁边——理由是「两个都是指着画面」。
用过一轮发现不对：手不是一种**画什么**，它是对缩放产生的后果的补救。
把它和八个标记并排放，等于让人在「矩形」和「挪画面」之间做选择，而这两个不在一个层上。

现在中间那条读作：

```
[手]  缩放 −  73%  缩放 +  |  选择  裁剪  |  矩形 椭圆 箭头 钢笔 荧光笔 马赛克 序号 文字
```

三块各二：左撤销重做两个，右复制覆盖两个，中间其余全部。

### 19.3 竖线

两处分组靠竖线说话，不靠间距：一条在缩放簇与「选择/裁剪」之间，一条在「选择/裁剪」与八个标记之间。
间距只能表示「有点远」，竖线才能表示「这是另一类」。线的颜色用发丝边的墨，高度收到行的 60%——
和图标一样高的竖线会被读成第 12 个按钮。

### 19.4 最小宽度 860 → 780

上一轮 860 是因为右侧那块要塞下「缩放 + 复制 + 覆盖」三组，把中间那条挤得只剩 31 点。
这一轮缩放搬进中间、右侧回到两个按钮，中间立刻松了：980 宽时空 149 点。
重新量了临界点，780 时 49 点仍清楚分成三块：

```
bars: three, tightest gap 149 pt at 980 wide
bars: three, tightest gap 49 pt at 780 wide
```

数字是量出来的不是拍的这一点没变，变的是**量的是哪一次布局**——布局改了就得重量，
上一轮那个 860 在新布局里是浪费。

### 19.5 验收

```
place: the window opens under the strip and on the screen
bars: three, tightest gap 149 pt at 980 wide
bars: three, tightest gap 49 pt at 780 wide
zoom: the transform agrees with the drawing at both scales
zoom: 10-point steps 73% → 80% → 90% → 80% → 70%
pan: dragged 60,40 → moved 60,40; marks 2 → 2
drawer: follows the tool, and folds on a second press
drill: double-click crops, single click does not   200 × 140
italic: false → true → false; the caret field would use .SFNS-RegularItalic
check: same file twice → 1 window(s); then a second file → 2 window(s)
check: wrote width 17, read back 17.0
```

两张没自动化的仍然是那两张：光标落在浮条上是箭头不是十字（离屏里没有指针），
以及编辑器开在真面板下面（离屏里面板没起来）。

## 第二十节（第十七轮）：按钮角上的字母，和一个开关

用户要的是「不用记」：快捷键以特别小的字落在按钮右下角，不喜欢可以关掉。

### 20.1 字母落在哪几个按钮上

十一个工具各一个字母，别的按钮一个都不给。这不是省事，是口径：

- **工具键**（V G R O A P H M N T C）在这个 App 里**别处一个字都没写过**。
  没有菜单、没有快捷键面板、tooltip 原来写的也是同一个字母但要点着才有。
- **命令键**（⌘Z ⌘C ⌘S ⌘+/−）是跨应用的肌肉记忆，提醒一次的价值近似于零；
  而 `⇧⌘Z` 在 26 点宽的撤销按钮里塞不下——三个字形已经占掉半个按钮。

所以设置页那一行把话说全：「复制、覆盖、缩放用的是通用 ⌘ 组合键，不标」。
把漏掉的部分先说清楚，比让人发现一半再猜为什么强。

### 20.2 画法

6.5 点、semibold、`labelColor` 的一半，右对齐落在按钮右下角，距右 2.5 点、距底 1.5 点。
六点五不是估的：在 17 点的图标下面，再大一档就读成第二行标签，再小一档就没了。

按钮本身**一个点都没动**（仍是 30×26，间距 4 点）。字是给手边的按钮加的一个记号，
不是为了字去重新排按钮——见 20.6，这一条是被用户按回去过一次之后才定下来的。

**颜色不用 clay**：clay 在这个窗口里只有一个意思——「这个在我手上」。
角上的字要是借了它，每个没选中的按钮都会回答错这个问题。

### 20.3 开关与「已经开着的窗口」

`ShortcutHints.isEnabled` 落 `UserDefaults`（`editorShortcutHints`，默认开），
setter 里发一条通知，`EditorWindowController` 收到后重刷 11 个 chip 的 `hint`。
走通知而不是「下次开窗生效」：设置页写着「改动立即生效」是这套窗口的既有口径，
一个要重开窗口才生效的开关看起来就是坏的。

`ToolChip.hint == nil` 同时表示「这个按钮没有键」和「开关是关的」——窗口在
`applyShortcutHints()` 里做一次决定，画的时候不再问 `UserDefaults`。

### 20.4 顺带：设置页终于能被看见了

设置页是唯一一处 SwiftUI，之前没有任何办法在离屏里看它。加了
`CLOTHESPEG_SETTINGS_SHOT=<png> [CLOTHESPEG_SETTINGS_PAGE=general|invocation|…]`，
`SettingsView` 也因此多了一个 `section:` 初始化参数（默认 `.general`，别的入口不受影响）。

**第一版打印了一个高度，然后发现它永远不变**：`NSHostingView` 拿到 frame 之后
`fittingSize` 就是那个 frame，六个页面读出来全是 588。那句提示读起来像证据，
其实什么都没测——已经删掉，只留图。这是「只在默认状态下成立的检查等于没有检查」
的同一个病的另一面：**一个不可能变化的数字，等于没有数字**。

### 20.5 验收

```
hints: 11 of 11 corners carry a key — V G R O A P H M N T C
hints: switch off → 0 corners, back on → 11
hints: the switch reaches a window that is already open
```

外加三张图：开着、关掉、深色。深色那张第一版里没有字母，原因是
`.._NOHINTS` 把 `UserDefaults` 写成了 `false` 就再没还回去——
**演练改了用户真实偏好**。现在进出都夹在 `defer` 里，按原样还：
「从没选过」和「选了开」是两个状态，不能都还原成 `true`。

### 20.6 补：两端的留白（用户两次看图之后才定）

第一版做完，用户截图指出最边上那颗字母贴着圆角。我先改的是**按钮宽 30 → 34**，
理由写得挺像回事：图标居中后左右各 8.5 点，字母 4 点右缩进正好落进留白。

**用户第二次看图把这个改回去了**：「原来的间距没有问题，不用改，只有两侧的宽度需要增加…
按钮之间的判定不需要增加，保持原来的就可以了。」

这句话是对的，我上面那套理由只顾了字，没顾手：按钮的间距是给手排的，
把它们各放宽 4 点，中间那颗「矩形」就往右挪了 22 点——一个用了两天的肌肉记忆被一个
角标推走了。**这是拿使用频率最低的东西去换使用频率最高的东西。**

定稿只改一处：

| 项 | 之前 | 之后 | 理由 |
|---|---|---|---|
| 浮条内留白（两端） | 7 | **12** | 只有最边上那颗字母需要离边界更远 |
| 按钮宽 / 间距 | 30 / 4 | **30 / 4** | 一个点都不动 |
| 字母缩进 | 右 2.5 / 底 1.5 | 右 2.5 / 底 1.5 | 不动 |

**代价**：三个浮条各宽 10 点，中间那条与右侧那条的间隙因此少 10（中间居中、右侧贴边，
两边各让 5）。量出来 980 宽时 134 点（原 149），780 宽时 34 点（原 49），所以
**最小宽度回到 780**——上一轮为了放宽按钮抬到 850，这一轮又降回来了。

```
bars: three, tightest gap 134 pt at 980 wide
bars: three, tightest gap  34 pt at 780 wide
bars: three, tightest gap  14 pt at 740 wide
```

抽屉里那三颗（填充 / B / I）也回到 30 宽，抽屉跟着窄回 12 点。

**记一笔**：把一个角标加进一排已经排好的按钮里，能改成「只给边上的让位」就不要
「整体重排」。前者只动两个数字，后者动的是别人的手。

### 20.7 T 的角标为什么高出一截

改完留白，用户第三次看图问了一句：右下角那个 `T` 的高度比别的按钮高。

**第一版诊断是错的。** 我以为是字形来源不同——其余十个是 SF Symbol，文字工具自绘
`"Aa"`——于是给 `ToolChip` 加了 `intrinsicContentSize`（30×26），想让「stack view 问
的地方」给出同一个答案。编译通过，跑演练，打印出来了：

```
G bounds (0,0,30.5,33)   V 33   C 33   R 31   O 32   A 29   P 31   H 33   M 32   N 32   T 26
```

一个数都没变。这层覆盖是白写的。

**真因在 `alignmentRectInsets`。** `NSButton` 会报一组内缩，描述「如果我有 bezel，
它该在哪儿」，而这组数随字形变：

| 图标 | top | bottom | right | 得到的 frame 高 |
|---|---|---|---|---|
| 手 `hand.point.up` | 4.0 | 3.0 | 0.5 | 33 |
| 铅笔 | 2.5 | 2.5 | 0.5 | 31 |
| 矩形 | 2.5 | 2.5 | 0.0 | 31 |
| 自绘 `Aa` | 0.0 | 0.0 | 0.0 | 26 |

`NSStackView` 是按 **alignment rect** 排版的，所以 `width == 30 / height == 26` 这两条
约束管的是对齐矩形：frame 被内缩撑大，撑多少取决于里面画的什么。而 `drawHint` 的 `y`
是从 `bounds` 算的（`bounds.maxY - size.height - 1.5`），`bounds` 就是被撑大的那个
——十一个角标于是落在十一个高度上，`T` 因为一个内缩都没有，比其他十个高出 3.5 点。

修法一行，因为无边框按钮本来就没有 bezel：

```swift
override var alignmentRectInsets: NSEdgeInsets { NSEdgeInsets() }
```

装回去以后十一个 chip 的 `bounds` 全是 `(0,0,30,26)`、`frame` 全是 `origin.y = 0`、
角标原点全是 `16.5`。顺带的好处：选中态的 clay 方块（也是从 `bounds` 画的）以前在
不同工具下是 26…33 高，现在一样大。

**这一轮真正学到的是两条。**

其一，一层没验过的覆盖不要叠第二层。`intrinsicContentSize` 那次如果第一步就先把
`bounds` 打出来，就不会写它，也不会在注释里把原因写成错的（那段注释已经按真因重写）。

其二，**像素量法骗了我**。在 `hints-on.png` 上量「每个角标的墨迹行区间」，读数显示
T 与其余齐平（131–140），与调试打印的 4 点差完全相反——因为采样窗口落在了 `"Aa"`
图标本身的黑墨上。同一批读数里还有第二个错：chip 的 frame x 是以 select=`V`（150）标定
的，我按 `C`（183）算，整体偏了一格，九个读数全错却全都「自洽」。

**所以这一类检查交给数值，不交给眼睛。** `ToolChip.hintBaseline` 用与 `drawHint`
同一份算术算出角标的落线（转到 contentView 坐标），`previewHintBaselines` 把它交给
hintDrill：

```
hints: the corners are drawn at 658.5 658.5 658.5 658.5 658.5 658.5 658.5 658.5 658.5 658.5 658.5
hints: all eleven on one line (spread 0.0 pt)
```

**并且先摘掉修复，看它会不会喊**：

```
hints: the corners are drawn at 655.5 655.5 656.0 655.5 657.5 656.0 655.5 656.0 655.5 658.5 655.0
hints: FAILED — the corners span 3.5 pt
```

会喊，才留下。一个不会失败的自检等于没有自检。

## 第二十一节（第十八轮）：滑块的值跟着手走

用户一句话：「调整滑块要实时显示调整的值，而不是松开后才显示值。」

### 21.1 一行开关，两件事

`NSSlider.isContinuous` 决定拖动过程中要不要发 action。编辑器里两个滑块
（粗细 / 不透明度）一直设成 `false`，理由是注释里写着的：一次拖拽会写出十几个
撤销步骤。这个理由在当时成立——但那是因为当时的落盘和撤销是同一个动作。

现在两件事已经分开了，开关就能打开：

```swift
slider.isContinuous = true
```

- **撤销**：`EditorDocument.beginEdit(tag:)` 本来就按 tag 在 1.2 秒窗口内合并，
  tag 是 `"style-\(field.rawValue)"`，一次拖拽里始终不变 → 一次拖拽一条历史。
- **落盘**：这是唯一真正需要等的地方。`mutateStyle(tag:persist:)` 多了一个参数，
  拖拽中 `persist = false`，只改内存里的样式；松手后写一次。

### 21.2 「松手了」是哪一个时刻

`NSSlider` 的跟踪循环整个跑在 `super.mouseDown` 里面——鼠标按下去这个调用就不
返回，直到鼠标弹起。所以 `super.mouseDown` 之后那一行，是唯一诚实的「拖拽结束」：

```swift
override func mouseDown(with event: NSEvent) {
    isBeingDragged = true
    super.mouseDown(with: event)   // 整个拖拽都在这行里面
    isBeingDragged = false
    onCommit?()                    // 写一次盘
}
```

类叫 `ValueSlider`，放在 `EditorChrome.swift` 里（控件都住那儿）。属性叫
`isBeingDragged` 而不是 `isTracking`：`NSCell` 对后者另有定义，控件和它的 cell
对同一个词有分歧正是 bug 的来源。

### 21.3 验收

拖拽没法在离屏里做——跟踪循环会把 run loop 拿走不还——所以演练做的是这个手势
**对 App 做的事**：把滑块标成「在手上」、报一个值、在松手之前看标号。

```
slider: both sliders report while the knob moves
slider: the knob is heard from before it is let go
slider: 粗细 25 → 粗细 12 with the knob still held
slider: the caption follows the knob, not the mouse-up
slider: nothing written to the style file mid-drag (still 24.6)
slider: letting go writes it once (12)
```

前两行是**机制**，后四行是**行为**。分开写是因为它们各自会坏：把
`isContinuous` 改回 `false`，机制那两行立刻变成

```
slider: the sliders wait for the mouse-up
slider: FAILED — the knob only speaks on release
```

而「标号跟着 action 走」那几行照样通过——因为演练是自己发的 action。**这正是这一轮
值得记的地方：只验行为不验机制，会漏掉用户真正抱怨的那一半。**

（演练会写一次 `editorToolStyles`，所以进出都按原样还；`EditorStyleStore.defaultsKey`
从 `private` 放开成 `internal`，让演练看的是同一个键而不是抄一份字符串。）
