# 截图与编辑器路线图

> 2026-11-02 建立。本文是 `dev-backlog.md` 的上游长文档：backlog 记"待做条目"，
> 本文记"这些条目为什么这么排、分几步、每步怎么验收"。
> 与 backlog 的对应关系：#20 编辑器、#21 截图、#22 实时标注。

## 0. 结论

三条工作线，不是两个版本。

| 线 | 内容 | 技术性质 | 排期 |
|---|---|---|---|
| A | 图片编辑器 | 纯应用内，离屏渲染，无权限 | 1.12（先做，独立发版） |
| B | 抓屏与分流 | 需要屏幕录制权限，全屏遮罩窗口 | 2.0（含 A 的能力） |
| C | 实时屏幕标注 | 透明覆盖窗 + 事件接管 + 多 Space | 3.0（另立项，先出 RFC） |

A 是枢纽：B 的"截完即编辑"和 C 的"笔迹渲染"都要用它。先做 A 的判断成立。

## 2. 功能清单

### A. 1.12 图片编辑器（MVP）

工具（第一版只做六个）：矩形、箭头、自由画笔、高亮、马赛克（像素化）、裁剪。
颜色与粗细**按工具各自记忆**，这是"用久了顺手"和"每次都要重调"的分界。

出口三个：
- `Done`（⌘↩）写回原文件，绳子上的卡重绘缩略图
- `Copy`（⌘C）写剪贴板，不动文件
- `Save As`（⌘⇧S）另存，原图不变

明确不做（第一版）：
- 非破坏编辑（sidecar + 重新渲染，成本翻倍，当下痛点不在这）
- 文字工具（`NSTextView` 叠加 + first responder 是独立一个大坑，放 1.13）
- 编号、测量、聚光、水印（1.13 起按需加）
- 背景/圆角/阴影/预设（那是"出图好看"，不是"标清楚"）

### B. 2.0 抓屏与分流

一个快捷键 → 冻结帧全屏遮罩 → 三选一选区 → 松手出动作条。

选区：
- 拖拽画框
- 悬停整窗高亮，单击即选（`Space` 在拖拽与整窗之间切换，这是系统截图和三家开源工具共同的肌肉记忆）
- 全屏：`⌘A` 或直接双击遮罩
- 八点句柄调整，框内拖动整体平移

动作条（松手后出现在选区下方，超出屏幕则翻到上方）：

| 动作 | 默认 | 说明 |
|---|---|---|
| 复制 | ⏎ | 写剪贴板并关闭，零额外操作 |
| 编辑 | ⌘E | 进 A 的编辑器，改完可直接复制 |
| 保存 | ⌘S | 落 `Inbox.folder` 或设置里的目录（沿用 #2） |
| 钉住 | ⌘P | 与 #17 桌面贴图合流，不再是另一套 |
| 删除 | ⌫ | 不写盘、不留卡 |

无条件行为：**无论按哪个动作，截图都进绳子（一张卡）**，去重靠 4.6。

### C. 3.0 实时屏幕标注

- 全屏透明画布，可跨 Space、多显示器各自一层
- 画笔、箭头、矩形、聚光、放大镜、激光笔
- 笔迹 N 秒淡出（N 可调），`Esc` 清空，再按快捷键退出
- 不接管普通点击（否则等于锁屏），只接管绘图工具的按下

明确不做：录屏、把标注烧进截图（那是 2.0 的事）。

## 3. 技术方案

### 3.1 抓屏

`SCScreenshotManager.captureImage(contentFilter:configuration:)`，macOS 14+ 正好卡在最低系统线上。流程与 screen-translate 一致，值得照抄：

1. 抓**整块虚拟屏**成一张 `CGImage`
2. 用它铺满无边框遮罩窗
3. 用户在静态帧上选、画

好处是零闪烁、无需实时流、遮罩上所有绘制都是对同一张位图的操作。整窗列表用 `SCShareableContent.windows`（比 `CGWindowListCopyWindowInfo` 多拿到 `SCWindow.frame` 和 owningApplication，省一层坐标换算）。

### 3.2 选区窗口

- `NSPanel`，`styleMask = [.borderless, .nonactivatingPanel]`，`level = .screenSaver`
- 必须 `canBecomeKey = true`，否则收不到键盘（`Esc`/`Space`/`⏎`）
- 每块屏幕一个实例，坐标用 `NSScreen.frame` 独立算，不要做全局虚拟坐标
- 遮罩层暗化用 `NSColor.black.withAlphaComponent(0.35)` 整体铺，选区内再重绘原图，与 2 段式一致

### 3.3 编辑器架构

三层，别合成一层：

| 层 | 职责 | 建议文件 |
|---|---|---|
| 模型 | `Document`（原图 + `[Annotation]` + 画布尺寸）、`Annotation` 协议（`draw(in:)` / `hitTest(_:)` / `handles`） | `EditorDocument.swift`、`Annotation.swift` |
| 渲染 | 一个 `CGContext` 渲染函数，**导出和屏幕显示走同一份代码** | `EditorRenderer.swift` |
| 交互 | 工具状态机、命中测试、句柄拖动、撤销栈 | `EditorCanvas.swift` |

两条铁律：

1. **坐标系一次定死**。图片像素坐标是唯一真源，视图坐标只在外层换算。Retina 2x 的坑就在"我以为是点，其实是像素"。
2. **撤销用数组快照**。标注对象轻，快照整个 `[Annotation]` 比实现命令的 undo/redo 省一半代码，第一版够用。

参考实现：Screendrop/Framecho 的 `Engine/`（`Document.swift`、`AnnoEditor.swift`、`GeoPaths.swift`、`Measure.swift`），CC0，可以直接读来对结构，不要整体搬（8 万行的工程，摘思路比摘代码快）。

### 3.4 数据与写回

沿用现有契约，不新建模型：

```
截图 → 写 PNG 到 Inbox.folder → Payload.image(url) → Pegged → Line
编辑 → 原地改这个文件 → Markup.onSaved(url) → Line.reloadThumbnail
```

`Markup.swift` 的 `onSaved` 和文件夹监视可以原样保留：编辑器写回后手动调一次 `onSaved`，比等文件事件更快也更准。旧的 Preview 路径留一个设置开关做回退，别一次删干净。

### 3.5 权限与首启

屏幕录制权限是全新的一道门（现在读文件夹不需要权限）。三件事必须做：

1. 首启引导里加一行"屏幕录制"，实时显示状态（与 backlog #10 合成一件事）
2. 快捷键触发时若未授权，弹系统授权并给"打开系统设置"按钮，别静默失败
3. 授权后**可能要求重启进程**才能抓屏，这条要在引导里直说

### 3.6 去重（必须和 2.0 同版）

截图写剪贴板后，`ClipboardWatcher` 会在下一次 `changeCount` 把它再抓一次，变成两张卡。做法：

- 生成 64 位 dHash（图片缩到 9×8 灰度）
- 写入剪贴板时登记 `(hash, 时间戳)`，Watcher 见到同 hash 且在 3 秒内就跳过
- 反向同理：Watcher 抓到的图片若与 3 秒内的截图 hash 相同，只更新不新增

这条不解决，2.0 一上线就是肉眼可见的 bug。

## 5. 交互细节

从三家开源工具对照出来的共同点，说明是肌肉记忆，跟着做：

| 动作 | 约定 | 出处 |
|---|---|---|
| 拖拽中按 `Space` | 切到整窗选择 | 系统截图、Screendrop 0.35.3、screen-translate |
| 双击选区 | 直接复制 | screen-translate、Framecho |
| `Esc` / 右键 | 取消 | 三家一致 |
| 八点句柄 | 四角四边都能拉 | 三家一致 |
| 数字键 | 单个工具快捷键 | Framecho、Snaplate |

Clothespeg 自己的两条，别照抄别人：

1. **动作条不堆叠**。Framecho/Screendrop 用"堆叠预览栈"，那是它们的主界面。我们的主界面是绳子，堆栈会打架。截图只出一条动作条，不用就消失。
2. **截图卡要有身份**。绳子上现在只有"复制来的"和"写的便签"两类，截图是第三类。给一个极轻的标记（比如夹子的颜色），否则用户分不清"这张是我截的还是我复制的"。

## 6. 风险

| 风险 | 后果 | 处理 |
|---|---|---|
| 文字工具 | `NSTextView` 叠加层的 first responder 与工具状态机抢焦点，容易做出一堆"文字输入不进去" | 1.13 单独做，别混进 MVP |
| Retina 坐标 | 导出图糊 / 标注偏移半个像素 | 步骤 0 就定死像素坐标 |
| 屏幕录制权限 | 首次授权后需重启、多显示器下部分屏黑 | 引导里写清楚，失败给明确提示 |

### 2026-11-02 第二轮：五个工具

工具顺序即工具条顺序，快捷键 R / A / P / H / M。

- `ArrowMark`：箭头长度取 `clamp(箭头长/5, 线宽, 线宽×3)`（借 Framecho 的公式，比固定 10pt 好：
  短箭头不会顶个大脑袋）；箭杆缩到头部长度的 75% 处，避免圆头从三角里戳出来。
- `PointsMark` 基类：笔、荧光笔、马赛克共用采样 + 二次贝塞尔过中点平滑 + 折线命中测试，只在"画什么"上分家。
  采样有 0.5pt 阈值，否则 4K 图一次拖拽能攒几千个点。
- `StrokeMark`：荧光笔 = 同一条笔画，alpha 0.38、方头、bevel join、默认 18pt 宽。
- `MosaicMark`：用 `replacePathWithStrokedPath()` 把笔迹变成轮廓再 `clip`，铺预先像素化的底图。
  底图 `EditorDocument.pixelated` 懒加载，缩到 1/16 再最近邻放回（16px 块：再小字就还认得出来，不算打码）。
- 每种工具记自己的颜色和线宽（`toolColors` / `toolWidths`），否则拿起荧光笔会把已经画好的矩形改成黄色。
- 脏标记：画完即 `saved = false`，关窗会问；之前只有撤销/重做会置脏。

### 2026-11-02 第三轮：编辑期内可改 + 干净底图

用户拍板："先做编辑期内可改"，"现在就存一张干净底图"。没做的（明确留到后面）：跨会话持久化标注（sidecar）。

- **`select` 是第一个工具，也是打开时手里的那个**。窗口一开就握着矩形，等于把每一次"只是看看"的点击都画成一个框。
- 选中三件套：`hitTest` 自上而下（最后画的最先被点中）、拖动、`⌫` 删除、`Esc` 取消选中；
  改颜色/线宽直接改到选中的那个 mark 上，不动工具自己的记忆（否则改一个箭头会把之后所有箭头一起改掉）。
- **命中测试 slack = 6 屏幕点 ÷ scale**：宽恕要按手在屏幕上判断，写死成图片像素的话，5000px 的图缩进窗口后 1pt 的线根本点不到。
- **矩形只认边框不认内部**（Illustrator 对无填充图形的做法）。若认内部，一个圈住整段话的框会吞掉框内一切点击，下面的箭头永远选不中。代价：想拖一个空心矩形得按住那根线。
- **撤销栈的深拷贝是真 bug 修复，不是重构**：mark 是 class（为了能原地拖动），快照存引用的话拖一下所有快照跟着动，撤销就变成"按了没反应"。`clone()` 进协议、`snapshot()` 改成 `map { $0.clone() }`。
- **`beginEdit(tag:)` 合并**：颜色面板一开就按鼠标经过的每个色号回报一次，一次决定要变成十几步撤销。同 tag 1.2 秒内视为同一次编辑；`undo/redo` 清 tag，否则撤完再调滑块会并进上一条。
- 拖动只在**第一个像素移动时**取快照（`dragged` 标志），所以"点一下看看"不会往撤销栈里塞空操作。
- 撤销/重做会把整数组换成克隆，选中的人已经不在图上 → `pruneSelection()` 老实丢掉选中，而不是让一个幽灵对象继续被拖。
- 工具栏语义随选中切换（`refreshControls()`）：选中 mark = 控制它；握着工具 = 控制下一笔；空手空选 = 两个控件置灰。马赛克没有颜色，选它时色板禁用。
- 线宽滑块 `isContinuous = false`：拖动过程不回报，松手才改一次。范围会跟着 mark 走（26pt 的马赛克刷超出滑块默认上限 20，不退让就会被悄悄削成 20）。
- `EditorStore.keepBase`：第一次打开时把**还没被画过**的图另存一份，永不覆盖，按路径 FNV-1a 命名（两个 `image.png` 在不同文件夹会撞名）。
  现在没有读者，但"Done 是写回原文件"意味着第二次开会话时底图已经带着上次的箭头——这份副本是唯一能回到干净状态的东西。

### 2026-11-02 第四轮：裁剪 + 中文词条

- **撤销快照从 `[EditorMark]` 变成 `State { source, marks }`**。裁剪会让图片本身换一张，只存标注的话，撤销把箭头放回去、底图还是裁过的，两边对不上。
  `pixelSize` 因此从存储属性改成 `source` 派生的计算属性，改一处就够。
- `CGImage.cropping(to:)` 不重编码、不损失质量，所以直接换 `source`，不在原图上挂一个裁剪矩形到处减坐标。
- 框外的标注直接丢：留在画布外既看不见也选不中，撤销会连它们一起带回来。
- 马赛克要单独处理：它的 `layer` 是**当时那张**像素化底图，裁剪后坐标虽然平移了，铺的还是旧图。所以裁完如果有马赛克在图上，重建一次 layer 并同步 `pixelSize`；没有就一次都不算。
- `pixelated` 从 `lazy var` 改成 `cache + getter`，否则裁剪后拿不到新的。
- **回车一次只有一个含义**：有裁剪框待应用时「应用裁剪」，否则「完成」。做法是两个按钮交换 `keyEquivalent`，不是都挂着 `\r`。
- 裁剪按钮**常驻、按状态置灰**，不做隐藏。`NSStackView` 隐藏后的重新挂载位置不可靠（可能跑到末尾），而且会凭空出现的东西没人能发现。
- 空点（按下没拖）不清掉已有的裁剪框：看一眼图片不该丢掉刚画的框。小于 8px 的框才当手滑丢掉。
- 顺带补了 `zh-Hans` 缺失的词条：前几轮七个工具名、撤销/重做、三条窗口文案在中文界面下一直显示英文（`L()` 找不到键就回落英文）。

### 2026-11-02 第六轮：序号圆

第五轮（S1–S7，两行属性条、样式模型、马赛克块大小、文字工具、写回原图、椭圆填充、裁剪比例）的取舍写在 `notes/editor-plan-v2.md` 的 §8，这里只记第六轮。

- 工具键 `N`，按下即落一颗，不拖框：序号是点，不是形状。连点就是 1、2、3。
- **数字不进 mark**。`NumberedMark` 只有一个 `number` 字段，由 `EditorRenderer.drawMarks` 每画一遍数一遍；删掉第二个，后面自动补位，导出走同一个渲染器所以文件与预览永远一致。
  存数字的方案在删除时要重排、在导出时要重算、在撤销时要恢复，三处都要记得，而"数一遍"这三处都不用记。
- 数字用 `contrastInk(for:)` 选黑白：亮度 0.65 以上用黑字，否则白字。黄底白字不是数字，是一团糊。
- **两个排序坑，编译期都不报**：
  一是草稿原先单独调一次 `drawMarks`，计数器从 1 重来，第三颗盘子在按下到松开之间先闪一下「1」；
  二是原先把正在编辑的那一笔 `filter` 掉再数，被跳过的那颗不占号，第二颗立刻变成「1」。
  修法是给 `drawMarks` 加 `skipping:`——**跳过绘制但照样计数**，画布把草稿 append 进同一个数组、只调一次。
  序号是从列表位置派生的东西，就只能在拆分之前的那份列表上算。
- 两位数（10 以后）字号从 `radius × 1.45` 起算，量出来超过半径的 1.7 倍就等比缩小：盘子按用户要的大小画，不为第十颗整体放大。
- 属性条上这个工具的宽度槽写「大小」不写「粗细」：同一个 `width` 字段，30 对画笔是笔宽、对序号是直径。给 `StyleField.caption` 多带一个名字参数解决。
- 这一轮第一次用无头渲染验证：`xcrun swiftc` 把 `Localization / EditorStyle / EditorMark / EditorText / EditorDocument` 加一个临时 `main.swift` 编成命令行程序，用 `flattened()` 输出 PNG，再逐张看图。
  比开 App 手点快得多，而且能查出"字是反的/上下颠倒"这类只有看图才发现的问题——Core Text 在翻转的绘图上下文里画出来是反的，这个风险真实存在，只是这次没踩到。
### 2026-11-02 第七轮：手感与打字

工具齐了以后，缺的是"点下去之前就知道会发生什么"。这一轮四件事，都不加工具、不加槽位。

- **光标随工具变**。九个画图工具一律十字线（握着工具时手里的问题是"到底落在哪一像素"），选择工具保持箭头（箭头就是"搬东西"的形状），文字工具用 I 形（唯一一个所有人都读成"在这儿打字"的形状）。
  实现是 `resetCursorRects` + `addCursorRect`，工具切换时 `invalidateCursorRects`。**还要在 `setFrameSize` 里也失效一次**：光标区域是按 `bounds` 铺的，第一次铺可能发生在这个视图还没进窗口的时候，光靠切换工具会让功能看着像没生效。
- 选择工具拖标记时变**握拳**，松手立刻变回箭头（不能等下一次鼠标移动，否则手上还捏着一把没放下的东西）。
- **写回原图之后按钮说一句「已写回」**，1.6 秒后变回。理由是脏标记清零会把按钮变灰，而灰按钮读作"不许点"和读作"办完了"一样自然；计划 §7.6 早就要求这件事。
  按钮宽度在创建时按当时的 intrinsic 宽度钉死——"已写回"比"写回原图"短，不钉的话文字一变，旁边的复制按钮就跟着往左挪几个点。
- **文字粗斜体走键盘（⌘B / ⌘I）**，不占槽位。`ToolStyle.isBold/isItalic` 和 `TextLayout.font` 早就在了，缺的一直是入口；
  两行属性条在 720 最小宽度下已经排满（实测 720 正好是底线），为两个按钮重新排版不划算。
  三个落点：正在打字的那个 → 选中的那段文字 → 文字工具的记忆，与其它样式改动同一套规则。文字工具的 tooltip 里写上这两个键，否则没人知道。
- 顺带修好两件一直不对的事：
  1. **打字时改字号不生效**。`mutateStyle` 原先只认 `canvas.selected`，而正在打的那一笔不是"选中"的，于是改的是工具默认值、屏幕上一点不动。
     现在 `mutateStyle` 第一落点是光标里那一笔，`refreshControls` 也跟着光标走（光标消失后 `endTextEditing` 主动通知一次，属性条回到描述工具）。
  2. **打字时 ⌘Z 撤的是整张图**。`NSTextView` 手建时 `allowsUndo` 默认 false，⌘Z 一路落到画布，撤掉的是上一支箭，而草稿还停在光标里——更糟的是撤销把 marks 换成克隆，草稿成了不在图上的幽灵，提交时会补一份重复的。
     现在光标打开时 ⌘Z/⇧⌘Z 只走文本框自己的 undoManager；撤不动就什么都不做，绝不落到图上。
- 验证：粗体/斜体/粗斜体三种在 `flattened()` 出的 PNG 里都真的显示出来了（`NSFontManager.convert` 对系统字体是有效的，`fontName` 从 `.AppleSystemUIFont` 变成 `.SFNS-Bold` / `.SFNS-RegularItalic` / `.SFNS-BoldItalic`），这条没有靠推理。
- 仍没做：文字对齐控件（`ToolStyle.alignment` 有字段无入口）、马赛克模糊/纯色两种模式、裁剪框边拖拽、另存为。

### 2026-11-02 第八轮：界面重做与五处修正

用户看着截图给的意见，前两条是"就这样"，后五条是改。改的意思不是给一条长工具条换个皮：
一张截图上十几个控件平铺在一行，读起来是"一堆按钮"，读不出"哪些是同一件事"。

**参数上的五处**：

| 项 | 之前 | 现在 | 为什么 |
| --- | --- | --- | --- |
| 箭头头部 | 与线同宽，看不出是三角 | `max(跨度/4.5, 线宽×3.5)`，上限线宽×6 与跨度×0.45 | 头部大小要跟**线的粗细**挂钩，不是跟线的长度 |
| 文字默认字号 | 16 | 32 | 16 是图注大小，而这是一张 Retina 截屏 |
| 文字字号上限 | 40 | 100 | 同一个滑杆要能写字，也要能写标题 |
| 序号圆默认直径 | 30 | 48 | 截屏上的标记是隔着一张桌子在看 |
| 序号圆上限 | 40 | 160 | 与画笔共用 `width` 字段，但两者的量级差一个数量级 |

`StyleField.range(for:)` 因此从存储属性变成按工具算的函数——同一个字段对不同工具不是同一个范围。

**粗体斜体从快捷键改回按钮**。第七轮拿 ⌘B/⌘I 省槽位，用户说"用图标加鼠标点击选取的方式去改变才是对的"。
判断标准其实很朴素：**快捷键是给高频动作的，加粗不是**。它是一次性的样式决定，用户想看见它现在是不是开着。
两个 `ToolChip` 挂在属性条托盘里（`bold` / `italic` 两个符号不本地化，可以安全用）。

**打字时按 ⌘Z 退字这件事去掉了**。那本来是第七轮顺手加的便利，用户说退格键就够。去掉之后留了一个尾巴：
`textDidChange` 里判"这次撤销把整段文字撤没了"，如果文字是**提交过又被撤掉**的，`endTextEditing` 不能再补一份空文字。
用一个 `textWasCommitted` 记住进入编辑时它是否已经在图上。

**三行托盘**是这一轮的主体。行各有各的职责——上行结束这张图（复制 / 写回原图 / 完成），中行选工具，下行调参数。
托盘是 `EditorGroup`（10pt 连续圆角、`labelColor@4.5%` 浅底、7/5pt 内边距），
按钮两种：`ToolChip`（30×26、选中 clay@15% 底 + clay 图标）与 `ActionPill`（胶囊，`isPrimary` 填 clay）。
上行右端是这一轮唯一的实心 clay 按钮——完成。

顺带把空着的第二个槽用上了：箭头、画笔、文字现在都能调不透明度（`fields(for:)` 里原本给它们的是 `nil`）。
一个装着真控件的槽，好过一个装着破折号的槽。

**两个只有在这个 bundle 里才出现的坑**：

1. **SF Symbol 会被本地化**。`textformat` 在装了 zh-Hans 的 app 里画出来是「格式」两个字，
   `character.cursor.ibeam` 画出来是「字」加一根 I 形光标。裸的 `.build/debug/Clothespeg`（没有 .lproj）不触发，
   所以单独测图标时完全看不出来——是打完包、渲染中文界面才暴露的。现在文字工具自己画一张「Aa」模板图。
2. **layer 颜色不跟外观**。托盘底色是 CGColor，赋值那一刻就把当前外观烧进去了。
   走 `updateLayer` + `viewDidChangeEffectiveAppearance` 重设，否则深色模式下托盘是浅色的。

**离屏渲染**：`EditorPreview` + `main.swift` 的环境变量钩子，`cacheDisplay(in:to:)` 把窗口画进 bitmap。
不依赖截屏权限，也不打扰正在用机器的人；同一个窗口能按工具、按深浅、按宽度各出一张图，还附带一个"有没有控件跑到窗口外"的检查。
两个坑：内容视图自己没有底色（窗口画在后面），所以要先给 bitmap 铺一遍 `window.backgroundColor`，
否则深色模式会渲染成"浅色底 + 浅色文字"的假 bug；外观必须在窗口建好之前定，颜色一旦烧进 layer 就不回头。

### 2026-11-02 第九轮：没有可调项的时候，和那条分界线

三行排好之后，图上最难看的地方是第三行的空状态：拿光标工具又没选中标记时，托盘里是两个破折号加两根推不动的滑杆。

第三行现在按状态给内容：不可调时整块托盘让位给一句 11pt 淡字（光标：「点一下图上的标记，就能改它的大小和颜色」；

- **harness 自己的坑**：新增的"渲染前先把九个工具各切一遍"是为了让 hide→show 之后的顺序被验证到，

### 2026-11-02 第十轮：工具搬到下边，颜色换成七个点

用户看过截图之后的四条：编辑栏放下边、颜色挪进属性行并给七个常用色、"自由裁剪"只在裁剪时出现、

- **布局**：顶栏（文件名 · 尺寸 · 复制 · 覆盖 · 完成）／横线／画面／横线／工具行／属性行。

  而裁剪改的就是这个数。现在 `pictureChanged()` 里重写，它本来就是"图变了"的唯一入口。
- **颜色**：`NSColorWell` 换成 7 个 `ColourDot`（红橙黄绿青蓝紫）+ 一个加号点开 `NSColorPanel`。
  面板选出的非常规颜色落在加号点上，属性行因此永远显示得出下一笔的颜色。

- **裁剪**：比例下拉只在裁剪工具下出现（和色点轮流占右侧同一个槽）；「裁剪」按钮取消，**双击框即应用**，回车也行。
  没有按钮之后回车的主人也换了：框在时回车应用、不在时还是完成——`cropChanged` 让完成胶囊交出 key equivalent，
  由画布 `keyDown` 接住。
- **脚本验收**（`CLOTHESPEG_EDITOR_PREVIEW_DRILL=1`）：造 `NSEvent` 按 拖框 → 单击 → 双击 发给画布，
  打印每一步像素尺寸。`1600×857 → drag 未变 → 单击未变 → 双击 345×242`。中间两次"没变"和最后一次"变了"一样重要。
  **坑**：事件不能走 `window.sendEvent`——窗口不是 key 时第一次 mouseDown 被窗口拿去激活自己，而窗口从没 orderFront 过就永远不是 key，
  于是事件被静默吞掉，表现为"代码没问题但什么都没发生"。改成直接调 `canvas.mouseDown/Dragged/Up`，命中测试单独 `hitTest` 断言。
- **顺带**：`imageRect` 加 `min(fit, 1)`，只缩小不放大。裁成 345×242 的角之后不会被放大 2.4 倍填满窗口——那是一张自己插值出来的图。

### 2026-11-02 第十一轮：三种离开的方式

用户看顶栏三颗按钮时的疑问：「复制和覆盖，再加上这个确定，是不是有点问题？」——很准，
**完成 = 覆盖 + 关窗**，同一件事说两遍，而且"完成"没说文件到底改没改。

- 现在三个按钮互不重叠：**取消**（什么都不做，脏的话弹三选一）／**复制**（这一版进剪贴板，关窗，不碰文件）／
  **覆盖**（写回原文件，写成功才关窗）。左到右按后果轻重排，覆盖是窗口里唯一的 clay。
- **复制也关窗**：三个按钮回答的是同一个问题"这一趟怎么结束"。它不弹丢弃确认——用户正在看的那一版已经在剪贴板上了。
  `⌘C` 仍是"复制、留下"；同一个动词的两半是两条动作，不是一条带开关的。
- **灰掉的 clay 不是 clay**：`isPrimary` 原先无条件填陶土橙，于是"没东西可写"的覆盖看起来像"快按我"。
  改成 `isPrimary && isEnabled` 才上 clay。
- **回车/⌘S**：回车改挂覆盖，因此干净的图上按回车什么都不发生；`⌘S` 加了 `guard saved == false`——
  不只是语义，`write()` 第一次执行会先备份原图，在没改动的图上"保存"会凭空造一份备份。
- **删掉**：窗口一关，「已覆盖」的回执没地方显示 → `written()`、`writeGeneration`、`ActionPill.isNote`、
  `setTitle`、`minimumWidth` 一起删。`minimumWidth` 当初就是为那句回执存在的。
- **查出两个词条重复**（`.strings` 同名键后者静默覆盖，`plutil -lint` 不管）：
  `"Done"` 定义了两次（完成 / 确定），后者赢了——设置页和便签提醒面板的 Done 一直显示「确定」，删掉后回到「完成」；
  这一轮新加的 `"Red"` 等七个颜色词条撞了便签颜色的 `红色/橙色/…`，删掉五个、只留 `青色`/`紫色`。
  查重脚本已写进计划 §13.5。

### 2026-11-02 第十一轮补充：填充开关不再当空槽

出四格对照图时发现的，和前面几轮同一个病：**不可用的控件留在原位，读作坏掉**。

- `fillToggle`（`square.fill`）原先常驻颜色托盘末尾，非矩形/椭圆时置灰 —— 一颗灰掉的小方
  看起来就是一块空槽。改成只有矩形与椭圆才让它出现（`colourTray.show`）。
- 即使在可用状态，开与关画的是同一个方块，只换颜色，开关本身说不清自己在哪一档。
  `ToolChip.symbol(_:)` 让图标跟着状态换：关 `square` / 开 `square.fill` + clay 底。

### 2026-11-02 第十二轮：名字只出现一次，工具回到头顶，一图一窗

- **名字删一处**：标题栏本来就有文件名，横幅又写一遍 + 一次像素数。现在标题栏写
  `名字 · 宽 × 高`，横幅撤掉；裁剪后 `updateTitle()` 重写，标题不撒谎。
- **取消删掉**：关窗就是取消，而它占着紧挨工具的最后一个位置，误点代价最高。
- **复制与覆盖不关窗**，关窗归交通灯。窗口不关就没有「按下去了」的反馈，于是图标变 √ 一秒
  （每个按钮单独计代，避免先按复制再按覆盖时 √ 卡住）。两者都改成图标，独立托盘放最右。
- **编辑栏回顶部**：上一轮的「手在图片附近」判断错了——手在屏幕上方交通灯那一带。
  现在工具行 + 动作一行、属性行一行、一条横线、画布。
- **一图一窗**：`ImageEditor` 改成 `[URL: Controller]`，同 URL 提到前面，不同 URL 各开一个。
  验收：同图两开 → 1 窗，换图 → 2 窗。
- **默认值 6 / 40，并且记得住**：`EditorStyleStore`（UserDefaults + JSON）存每个工具改过的数值，
  只在「没选中标记」时落盘。验收：写 17 读回 17。
- **比例 9 档**：自由/1:1/4:3/3:2/16:9/3:4/4:5/9:16/2.35:1；位置从属性行最右挪到裁剪时属性行第一个。
- **顺手补洞**：`windowShouldClose` 原来要求 `marks` 非空才问，**只裁不画时改动被静默丢掉**。
- **验收改造**：截图拍 frame view（标题栏才进画面）；新增 `CLOTHESPEG_EDITOR_PREVIEW_CHECK`。

### 2026-11-02 第十三轮：一条托盘、四个图标、一层点阵

用户拿了一张 CleanShot 的参考图：一条悬在图片上的圆角托盘，中间用细竖线分组，选中项是一块染色方块。
这一轮把窗口往那个形状收，顺带修了两个「看着像坏掉」的控件。

- **四个托盘合一个**：`[撤销重做][选择裁剪][八个标记][复制覆盖]` 曾经是四块圆角板子并排。
  现在一块托盘 + 三条 1pt 竖线（`EditorSeparator`）分组，并且**居中**——靠左会剩下右边
  三分之二空白，读作「这条工具栏没做完」。居中要**左右各一个 spacer**，只加一个不行。
- **复制/覆盖换衣服**：`ActionPill` 整个删掉，两个动作改用 `ToolChip`。理由不是审美统一，
  是**一个窗口只该有一种「亮」的含义**——原来那颗胶囊是窗口里唯一一种别的形状，看起来
  像从另一个程序搬来的。按下反馈也就借这一种：图标变 √、点亮 1.1 秒、灭回去。
  `ToolChip` 的禁用色从 `.tertiaryLabelColor` 换成 `labelColor@32%`：系统三级色在 17pt 图标上
  不是「不可用」，是「不存在」。
- **填充挪到数值身边**：`fillToggle` 从颜色托盘尾巴搬到属性行，紧跟两个滑块。它是「怎么画」，
  不是「什么颜色」；夹在七颗圆点后面时读作第八种颜色。图标换 `square.inset.filled`——原来的
  `square` 真正的毛病不是不够黑，是**和矩形工具的 `rectangle` 撞脸**，同一个空心方框。
- **两个图标改名**：`pencil` → `pencil.tip`（和荧光笔的粗笔头一眼分得开）；
  `square.grid.3x3.fill` → `circle.grid.3x3.fill`（方点阵在 17pt 上读作「表格」）。
- **点阵底**：12pt 间距、1.6pt 圆点、`labelColor@10%`。理由只有一个——**这个编辑器最常见的
  素材就是灰色 App 的截图**，灰图铺在灰底上，图片的边界会消失。点阵只在图片外，
  回答「图到哪儿为止」而不污染图片本身。实现是 `NSColor(patternImage:)` 平铺 12×12 tile，
  不是画几千个圆；tile 里烧了颜色，所以 `viewDidChangeEffectiveAppearance` 里丢掉重建。
- **斜体三段分开验**：字体层（两条路都得到 `.SFNS-RegularItalic`，画出图和正体差 4165 像素）／
  按钮→样式（走真实 `sendAction`，`isItalic` false→true）／样式→插入符（光标字体跟着变）。
  演练按两次把工具放回原处——**一个会改用户偏好的检查不是检查，是副作用**。
  这一版里斜体是通的；若用户仍觉得不斜，得先问清是「输入时不斜」还是「提交后不斜」。

### 2026-11-02 第十四轮：三条浮条、一个抽屉、一层缩放

参考图两条：CleanShot 那种悬在点阵上的胶囊，和「撤销重做一块、38% 加菜单一块」的布局。

- **三点分布**：左撤销重做、中工具、右「缩放 + 复制 + 覆盖」。位置本身开始说话——
  左上找历史、中部是手上、右上这一趟怎么结束且离工具最远。
- **浮起来**：两行 93 点全部还给画布，工具条压在图上。浮条换了新面
  （近不透明 + 发丝边 + 阴影），因为托盘的 5% 墨色压在图上是「把图抹了一层」。
- **抽屉**：属性栏挂在中间那条下面 8 点，同材质。跟着工具出现，再点一次当前工具收起。
  打开图默认（选择工具）它不存在——这就是「腾出位置」。
- **缩放**：`zoom: CGFloat?`（nil=适合窗口）+ `pan`，`imageRect` 是唯一变换点。
  按钮/菜单/⌘+/⌘−/⌘0/⌘1/滚轮平移/捏合。
- **拖拽淡出**：只在拖动时（单击不淡），0.32，抬手回来。
- **最小宽度 720 → 820**：三块滑进彼此的临界点量出来是 767，820 留 27 点。
- **两个真 bug**：① 色点的选中环在深色下消失（存档色是定值 sRGB，色点是动态系统色，
  `matches` 改成两种外观各比一次）；② 点阵 10% 太淡等于没铺，改 14% / 1.8pt。
- **验收**：新增 `bars:` 测距自检与 `CLOTHESPEG_EDITOR_PREVIEW_ZOOM` / `ZOOMDRILL` / `FADE`；
  裁剪演练改成瞄准图片坐标（原来裸视图坐标，fit 下碰巧对）。
  `zoom: fit 与 200% 存下同一个矩形`、`bars: 980→107pt / 820→27pt / 760→overlap`。

### 2026-11-02 第十五轮：十个百分点、一只移动的手、箭头回到按钮上

- **步进 ±10 个百分点**，第一步先对齐整十（fit 73% → 80%，不是 83%）。倍数制（×1.25）出的是
  125 / 156 / 195 这种没人要过的数；菜单里的 50/100/200/400 保留，那是「回到某个档位」。
- **第 11 个工具 `hand`（G）**：拖动即平移，开口手/握拳。滚轮平移一直有，但没人会先去滚一下
  再决定用不用。和选择并排，因为两个都是「指着画面、不改画面」。
- **光标穿到画布上**：浮条没声明 cursor rect，光标就落到下面的画布拿十字。群里加一行
  `addCursorRect(bounds, cursor: .arrow)`。这条没有自动化——离屏截图里没有鼠标。
- **最小宽度 820 → 860**：多的那 33 点让 820 宽时三块之间只剩 11 点。860 留 31 点。
- 验收：`zoom: 10-point steps 73% → 80% → 90% → 80% → 70%`、
  `pan: dragged 60,40 → moved 60,40; marks 2 → 2`、`bars: 860 → 31 pt`。

### 2026-11-02 第十六轮：开在面板下面、手与缩放同一条、三块各二

- **开在呼出面板下面**：原来是屏幕居中，正被面板压着，改一张图得先等它收回去。
  现在按 `LinePanel.current` 的真实下边缘摆，屏幕取**指针所在那块**，高度夹在可见区内
  且不低于最小高度。位置只在开窗时算一次，挪过之后不再被拽回去。
- **手挪到缩放旁边**：上一轮把它当第 11 个工具排进列表，理由是「和选择一样指着画面」——
  用过一轮发现它不在那一层：手不是一种「画什么」，是缩放之后拿来救场的。
  中间那条现在是 `[手] 缩放 | 选择 裁剪 | 八个标记`，两组之间两支竖线。
- **右侧回到两个按钮**：复制、覆盖。三块各二，平衡不再靠宽度凑。
- **最小宽度 860 → 780**：上一轮 860 是因为右侧要塞下缩放 + 两个出口，把中间挤到只剩 31 点；

- 验收：`place: the window opens under the strip and on the screen`、
